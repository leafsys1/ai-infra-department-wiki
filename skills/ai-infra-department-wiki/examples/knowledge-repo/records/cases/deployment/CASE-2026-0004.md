# 面向人的知识看板必须随 Skill 分发并经 HTTP 可直接访问

## 目标
让装了知识库 Skill 的同事能直接打开看板阅读知识，而不是只有作者本机能看到页面。

## 基线
看板文件只存在于 Skill 仓库的 `docs/` 目录：该目录不在安装器抓取的支持目录集合内，
SKILL.md 也未提及它，同事安装后既拿不到文件也不知道有这个东西。

## 变更变量
看板移入 `assets/dashboard/`（安装器可抓取目录）并列入支持文件清单；`build` 把它复制到知识仓的
`generated/dashboard.html`，与它读取的 `catalog.json` 同目录；页面在 HTTP(S) 下自动读取同目录
catalog，`file://` 下回退到手动导入。

## 受控与非受控变量
受控：Skill 版本、构建命令、浏览器无关的脚本执行环境。
未受控：浏览器差异与 `file://` 安全策略（按规范固定行为，但不做跨浏览器矩阵测试）。

## 执行步骤
1. 安装 Skill，逐字节比对安装产物与分发包。
2. 执行 `build`，检查看板是否出现在 catalog 同目录。
3. 通过 HTTP 访问，用 DOM 桩在 Node 中执行页面真实内联脚本并喂真实 catalog，断言渲染结果。

## 结果
- 安装产物 27 个文件逐字节一致。
- `build` 输出 `dashboard=<repo>/generated/dashboard.html`，与分发包字节一致。
- HTTP 匿名 200（访问控制在内网试点中关闭），点文件与路径穿越 404；看板脚本实际请求 `./catalog.json`
  与 `./graph-data.json`，渲染记录数与 catalog 一致、图谱关系数与 graph-data 一致（取证时为 14 节点 / 16 关系；
  语料增长后计数随之变化，该检查可随时重跑）。

## 结论
面向人的界面属于交付面的一部分，必须随包分发、由构建命令放到数据旁、并在无浏览器环境下也能
被程序化验证。只把页面放在仓库某个目录里，等于对安装者不可见。

## 适用范围与风险
适用于所有“文件随 Skill 分发”的场景。风险：`file://` 下浏览器禁止读取同目录文件，属安全策略，
不是路径缺陷；对外发布前仍需在真实浏览器中确认一次视觉呈现。
