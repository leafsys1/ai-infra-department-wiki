# 同一份交付包在另一台环境复现失败：同名镜像 tag 不是同一构建

## Goal

解释「同一份交付包、同样的 `run.sh`、同样的镜像 tag，在一台环境通过、在另一台环境失败」这类
假失败，并把排查动作固定成可复用的门禁，而不是每次重新猜环境。

## Baseline

视频生成类交付包依赖**自建镜像**（基于公共镜像 `quay.io/ascend/vllm-ascend:v0.23.0` 加依赖重建），
交付文档把「运行镜像」与「镜像摘要」都写成交付字段；复现方式是客户在目标环境执行 `run.sh`。
在这种形态下，交付包在两台环境上的 tag 完全相同，而两台环境上该 tag 指向的构建并不相同：
其中一台是本机早期用错误基础镜像构建的版本。

## Changed Variable

跨环境复现的**前置动作**：不再以「tag 相同」判定环境一致，改为比对镜像摘要
（`docker image inspect <image> --format '{{.Id}}'`）；摘要不一致时，用 `docker save` / `docker load`
传递确切构建，而不是在目标环境按同名 tag 重新拉取。

## Controlled And Uncontrolled Variables

- 受控：交付包内容与 `run.sh` 不变；推理参数与模型权重不变；目标环境的设备与驱动未改动。
- 未受控：两台环境的镜像仓库可达性与本地构建历史——正是本案例的变量来源，无法从交付包内部看出来。
- 未受控：目标环境上并发的其它容器可能占用设备，会产生与本案例同形的初始化失败（需另行排除）。

## Procedure

1. 在目标环境执行 `run.sh`，记录退出码与容器内报错阶段。
2. 比对两台环境上同名 tag 的镜像摘要。
3. 摘要不一致：从构建侧 `docker save` 出确切构建，在目标环境 `docker load`，替换本地同名 tag。
4. 在目标环境重新执行最小前向（冒烟），确认容器内适配层与 CANN 环境脚本加载成功。
5. 把摘要写进交付文档的「镜像摘要」字段，使下一次复现有可比对的身份。

## Results

- 失败侧的表现是**容器内环境初始化阶段**失败（设备/CANN 环境脚本相关），而不是模型或算子报错；
  同一交付包在构建侧环境上冒烟与完整两轮均正常结束。
- 比对摘要后确认两台环境上同名 tag 指向不同构建；把确切构建传递到目标环境后，同名 tag 下的构建
  与交付文档记录的摘要一致，冒烟与完整复现均通过。
- 交付文档侧的证据：`DEPLOY.md` 交付物表同时记录「运行镜像」与「镜像摘要」两行；跨环境复现记录
  另把公共基础镜像也固定到 digest。

## Conclusion

「同名 tag」只能说明标签相同，不能说明构建相同；交付包在一台环境通过、另一台失败时，**先比对摘要，
再怀疑模型与算子**。因果链是：自建镜像 + tag 可覆盖 → 两台环境同名 tag 指向不同构建 → 目标环境
容器内环境层缺失 → `run.sh` 在初始化阶段失败 → 比对摘要并传递确切构建 → 复现通过。

**边界**：本记录的具体摘要比对输出与旧构建摘要值保存在内部交付归档，未随本知识仓发布（受控指针），
因此状态为 `observed`；结论只覆盖「自建镜像 + tag 交付」这一类形态，不覆盖全部由公共镜像交付的包。

## Applicability And Risks

适用：交付依赖自建镜像、且镜像在两个及以上环境之间传递的所有场景；尤其是交付方与客户不共享镜像
仓库时。

风险：用 `docker save` / `docker load` 传递构建会带来镜像体积级别的传输成本，大镜像需要预留磁盘与
时间；把摘要写进交付文档意味着镜像一旦重建就必须同步更新文档，否则文档本身变成误导源。设备初始化
失败也可能来自权限或其它容器占用，本案例的处置动作不能替代对那两类原因的排除。
