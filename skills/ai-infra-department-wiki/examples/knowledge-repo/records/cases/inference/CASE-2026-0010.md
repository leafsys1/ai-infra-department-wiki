# scatter_nd_update_sk 最小 backport：端到端 6/6 为正，但逐毫秒归因只到 partially-supported

## Goal

把上游已合并的 `scatter_nd_update_sk` 以最小 diff 回移到当前生产栈，并回答一个问题：这个替换是否真的降低了冷 32K prefill 的服务端时延，而不是只在隔离微基准里更快。

## Baseline

- 生产栈里 `vllm_ascend/device/device_op.py` 的 7 个调用点指向 `scatter_nd_update_v2`；本轮只做加法，不删 v2 算子包，也不动 `minimax_m3.py`（非本场景模型）。
- R0016 生产 profiler 中同 shape 的 v2 行：Duration **2249.7 µs**，其中 `aiv_time` 只有 **204.2 µs**（`aiv_vec_ratio = 0.001`、`aiv_scalar_ratio = 0.685`、`cube_utilization = 0`）。

## Changed Variable

- `csrc/build_aclnn.sh` 在 `ascend910b` 与 `ascend910_93` 两个分支的 `CUSTOM_OPS_ARRAY` 各加一项 `"scatter_nd_update_sk"`（+2 行）；`device_op.py` 的 7 个调用点由 v2 改指 sk。
- 上游依据：`577fca5f9`（#15497，`[v0.26.0rc][Bugfix] Replace scatter_nd_update_v2 with scatter_nd_update_sk`）与 `7974247b6`（#15901，`[v0.26.0rc][Bugfix] Use full vector cores in scatter_nd_update_sk tiling`）。

## Controlled And Uncontrolled Variables

受控：同一冻结启动脚本、同一容器、同一批 shape、同一份 R0016 调用频次台账；两轮服务 A/B 的协议、负载、冷却控制与断言完全一致，只有臂顺序不同。

未受控：改指 sk 同时改变了 host 下发与 launch 形态（`shape1` 53.51 → 35.40 µs），而本轮没有在改动后做同点位插桩，因此无法把端到端节省逐项分解到算子本体。

## Procedure

1. 构建与加载证明：Level1 静态契约（schema / Meta 注册 / `aclnnScatterNdUpdateSk` 在 `libcust_opapi.so` 与头文件中的存在性）、Level2 编译（`csrc/build_aclnn.sh` 产出 run 包并安装）、以及运行期注册与负对照。
2. 正确性：上游 UT `test_scatter_nd_update_sk.py`，加本轮自建 8 个用例（重复 index、越界与 padding index、非连续 var、R0016 四个真实 shape），v2 / sk / numpy golden 三方按位比对。
3. 单算子三口径：仪表 A 逐调用 NPU event（batch=1，warmup 20 / repeat 100）、仪表 B batch20 摊薄常数项（repeat 100 与 150 两次）、仪表 C profiler 纯 kernel 时长（每臂每 shape 40 次、320 行 kernel 记录，按执行顺序归因，并与 R0016 shape 逐字比对）。
4. host 派发对照：无同步循环测单次派发 v2 与 sk。
5. 短服务配对 A/B：两轮，每轮 1 次 warmup（prompt #3，不计入任何中位数）+ 3 个受测 burst（prompt #0/#1/#2），c=1、temperature 0、max_tokens=8、streaming、单请求串行；每臂 8 卡全新引擎，两轮共 4 次起服。warmup 与每个受测 burst 之前都 `POST /reset_prefix_cache` 并拿到 `{"success": true}`（4 个臂各 4 次，全部第一次尝试即成功）；每个 burst 断言 `prompt_tokens >= 30000`，实测 12 个受测样本全部为 32768。第一轮臂顺序 candidate → baseline，第二轮用 `AB_ORDER=baseline_candidate` 反序。

## Results

- 正确性：上游 UT `38 passed, 14 warnings in 21.05s`（`ut_exit=0`）；自建 **8/8 通过**，v2 / sk / golden 三方按位一致。
- 加载证明（不能只凭编译成功）：`aclnn_lib_defines_sk = true`、`extension_has_sk = true`、`runtime_sk_registered = true`、`runtime_sk_correct = true`。
- 仪表 C（profiler 纯 kernel，R0016 频次加权）：v2 **13577.6 µs** vs sk **4776.9 µs** = **2.842x**。逐 shape：bf16 8096×512 3.28x、int8 indexer 2025×128 2.54x、fp16 scale 2025×1 **1.02x**、bf16 512 2025 2.54x。
- 仪表 B（batch20 摊薄常数项）：v2 14.101 ms vs sk 5.912 ms = **2.385x**；复跑 v2 14.051 ms vs sk 5.601 ms = **2.509x**。
- 仪表 A（逐调用 event，batch=1）：v2 21.581 ms vs sk 14.091 ms = **1.532x（未过 2x）**。该口径的噪声地板已被量化：空 event 窗口实测 **58.7 µs**、1 元素 torch 逐元素算子 100.9 µs、tiny scatter（两臂相同）130.7 µs；host 侧单次派发 v2 53.51 µs / sk 35.4 µs。**如果只承认逐调用 event 这一种口径，本轮应记 CONTINUE 而不是 KEEP。**
- host 侧：`shape1` 53.51 → 35.4 µs、tiny 38.87 → 33.86 µs，sk 在 host 侧也更便宜，不存在「kernel 变快但 launch 抵消」。
- 短服务 A/B：6/6 配对 TTFT 为正，合并配对中位 **−5.226985%**（total 6/6 为正、合并配对中位 **−5.114144%**）；合并臂中位 4.405161 → **4.160474 s**，比值 **1.058812**（等价 5.554542%）。第一轮 5.562175%、反序轮 4.789963%，两序同号、差额 **0.772212 pp**；候选臂两次独立引擎中位差 0.123 ms（0.003%），轮间波动主要在基线臂（1.27%）。12 个受测样本区间不重叠（候选最差 4.368996 s < 基线最好 4.369721 s）。同一 prompt 在两臂的首块文本完全相同；四份 serve 日志中的 `ERROR` 行全部出现在引擎 SIGTERM 关停瞬间。
- 复算：归档时用显式文件清单的复算器对四个原始 burst JSON 独立复算（不使用「最新一轮胜出」的 glob 语义），`cross_check_all_match = true`，最大绝对偏差 3.74e-05 pp。
- 现场异常（原样保留）：结案整理时发现 CANN AIC 异常转储，mtime 在本轮窗口内（2026-09-13 08:56:10），转储对应内核是**基线 v2 算子**、不是本轮新增的 `sk`；本轮所有已完成的运行全部 exit 0 且所有比较样本逐位一致；**触发该转储的确切进程与时刻未能确定，记为“未知”**。

## Conclusion

方向与量级成立、顺序偏差已排除：这个 backport 在冷 32K prefill 上带来真实的服务端 TTFT 改善（6/6 为正、合并配对中位 −5.226985%，达到该机制族 5% 目标），因此源轮次裁决 KEEP 最小 diff。

但**因果口径 = partially-supported（不得更弱也不得更强）**：生产关键路径上的收益大于「隔离 kernel 变快」的朴素外推——R0016 生产 profiler 里同一 v2 行的 duration ≈ 2249.7 µs，而本次隔离测量中位只有 223.9 µs（9.56x，加权口径 10.05x），且该生产行 `aiv_time` 仅 204.2 µs，说明生产流里 v2 占的是**时间轴上的 stall/串行**，不是向量工作量。改指 sk 同时改变了 host 下发、launch 与前后依赖的等待形态，而本轮没有做改动后同点位插桩。**方向与量级成立，逐毫秒归因不成立。**

必须同时记录的限定：按轮次规定的主仪表「逐调用 NPU event（batch=1）」结果是 1.532x < 2.0x，未过闸；本轮用两个独立口径交叉验证，并以端到端反序 A/B 作为最终裁决。

## Applicability And Risks

- 适用：当前 v2 算子在生产流里表现为时间轴 stall/串行的同类场景；替换只做加法（保留 v2 算子包），回滚成本低。
- 未覆盖（源里明确留白）：正式 48×1024 压测、把 sk 用于 `minimax_m3`、删除 v2 算子包、发布 GitHub。
- 风险：只采信「逐调用 event（batch=1）」单一仪表，会把 1.532x 当成收益上限甚至误判为无收益——该口径在空载设备上被固定开销（~58.7 µs/次）与 host 派发（34–54 µs）污染，必须先测噪声地板再解读比值。
- 风险：本记录是单实验室、单负载、单并行拓扑下的观测，未做跨模型/跨拓扑验证；`model_version` 与 `framework_version` 在源里没有给出，记为 unknown。
