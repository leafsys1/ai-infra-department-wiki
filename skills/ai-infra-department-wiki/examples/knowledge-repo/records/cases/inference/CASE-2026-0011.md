# DSA-CP A2 prefill：把完整 o-proj 权重收集前移，用 attention 主链覆盖通信

## Goal

消除冷 32K prefill 里暴露在 DSA-CP attention 输出后的 TP all-to-all：不去细分投影，而是把上游已经验证的「提前异步收集完整 o-proj 权重」调度回移到 A2，用 attention 主链覆盖通信时间。

## Baseline

- R0027 已测出每个冷 32K chunk 有约 **79 ms** 暴露在 DSA-CP attention 输出后的 TP all-to-all。
- 当前 A2 DSA-CP 的每个 rank 对本地 2024 token 计算完整 64 heads；在 o-proj 前把 activation 按 TP heads 重排并 all-to-all，通信位于 sparse attention 与 o-proj 之间，**无法被后续工作覆盖**。
- 当前 pin `f2f74a16c`（v0.26.0rc1）仍用旧手写池，并以 `device == A5` 硬门禁，A2 不命中。

## Changed Variable

- 真实入口：`AscendDSACPImpl.forward/_forward/_restore_tp_head_layout`。
- A2 且 `wo_a`/`wo_b` 均为 FLOAT（`AscendUnquantizedLinearMethod`）时启用现有 full-weight 调度骨架；**A5 原行为不变，其它量化类型不放开**。
- `wo_a` 是 output-sharded，沿逻辑 dim0 gather，并在完整路径重排为 `[group,input,rank]`；`wo_b` 是 input-sharded，沿逻辑 dim1 gather，HCCL 输入先 movedim 到 dim0、完整 view 再 movedim 回去。两者分片轴不同，所以不能只删掉 A5 条件。
- 两个 weight AG 移到 KV、Compressor、indexer、sparse attention **之前**异步发起；使用完整权重时跳过输出 activation A2A，o-proj 后恢复 TP 权重。
- 上游依据：`a533aed98 / #12982`（把 TP/full-weight switching 的分片规则移到量化方法，提交说明含 DeepSeek-V4-Flash W4A8、DSA-CP、TP、MTP 的确定性正确性验证）与 `b1098db5c / #15695`（明确 A5-only capability 是误收窄，恢复受支持 A2/A3 配置）。

## Controlled And Uncontrolled Variables

受控：每个全新引擎都是同一 1M、DP2×TP4/EP8、DSpark K7、DSA-CP 配置；每臂 1 次 warmup 不计入、随后 3 次受测；每个样本前 reset prefix cache，并断言 prompt tokens 为 32768；三个臂的顺序为 `candidate_v2 → baseline → candidate_reverse`（夹心，两侧都是 candidate）。

未受控：收益机制是把同阶 weight communication 与 attention 主链重叠，而不是消除通信字节——Level 3 显示仍有约 **1.3–1.4 ms** residual。本轮输出只有 8 token，total time 改善主要来自 TTFT，因此**本轮不宣称 TPOT 改善**。

## Procedure

1. Level 3 最小验证（TP4、真实 C4 full-chunk 字节量）：量 activation tensor 与 weight shard 的字节、四 rank 裸 activation A2A 与双 weight AG 的耗时、两者与独立 device work 的重叠收益、以及 `wo_a(dim0)`/`wo_b(dim1)` 的重组一致性。
2. 小尺寸完整布局合同：baseline 的 activation-A2A + TP 局部 o-proj + reduction 与 candidate 的本地 token + 完整 o-proj 做 `allclose` 对照。
3. 冻结短服务 A/B：夹心顺序 `candidate_v2 → baseline → candidate_reverse`，按 prompt index 配对，比较 TTFT 与 total time。
4. 资源与失败面核对：加载权重、KV cache 占用、请求成功数与首块文本一致性。

## Results

- Level 3：activation tensor **132 MiB/rank**；两份本地 weight shard 合计 **32 MiB/rank**，完整池合计 **128 MiB/rank**。四 rank 裸 activation A2A 约 **1.84–1.94 ms**，双 weight AG 约 **1.91–1.97 ms**；与约 **3.05 ms** 独立 device work 重叠后，相对 `work + activation A2A` 每层稳定节省 **0.48–0.56 ms**。`wo_a(dim0)`、`wo_b(dim1)` 重组均 **0 mismatch**。
- 布局合同：baseline activation-A2A + TP 局部 o-proj + reduction，与 candidate 本地 token + 完整 o-proj `allclose=true`，最大差 **1.1444e-5**（浮点归约顺序差）。
- 短服务 A/B（TTFT）：candidate_v2 `3.999689 / 3.796570 / 3.824064 s`（中位 3.824064）；baseline `4.308703 / 4.103816 / 4.157885 s`（中位 4.157885）；candidate_reverse `4.002508 / 3.865390 / 3.849442 s`（中位 3.865390）。第一组配对改善 `7.17% / 7.49% / 8.03%`，反序组 `7.11% / 5.81% / 7.42%`；**合并 6 对中位 7.295%，6/6 同向**。
- total time 合并配对中位改善 **7.344%**。9/9 measured 均为 32768 prompt / 8 completion，按 prompt index 首块文本一致，无请求失败。
- 资源与成本：baseline 加载权重 `25.3539 GiB`、KV cache `26.71 GiB`；两次 candidate 均为权重 `25.4789 GiB`、KV cache `26.58 GiB`，新增约 128 MiB 与完整权重池吻合，且无 OOM。
- 收尾：实验开关已移除，最终代码按安全类型/设备条件默认启用；所有服务按精确 PID 树停止，8 卡 idle。

## Conclusion

在 A2 DSA-CP 冷 32K prefill 上，把末端暴露的 activation all-to-all 换成前置异步的完整 o-proj weight gather 是真实有效的：夹心 A/B/A 的 6/6 TTFT 配对为正、合并中位改善 **7.295%**，超过同一通信调度机制族的 **5%** 目标；数值合同、token contract、首块文本、失败率、HBM 均通过，因此源轮次裁决 KEEP。

收益机制是**通信前移 + 与 attention 主链 overlap**，不是通信字节消失（Level 3 仍测得约 1.3–1.4 ms residual）。优化**只命中 prefill**，decode / spec-decode 保持原 activation all-to-all，因此本记录不宣称 TPOT 收益。

## Applicability And Risks

- 适用：A2 设备、`wo_a`/`wo_b` 均为 FLOAT 的 `AscendUnquantizedLinearMethod`、DSA-CP 的 prefill 路径；A5 原路径和其它量化类型不变。
- 未覆盖（源里明确留白）：**未跑 48×1024 正式吞吐 benchmark**；本轮主指标是冻结冷 32K TTFT/prefill period。
- 风险：新增约 128 MiB/rank 常驻权重池，显存紧张时需要重新核算；本记录是单实验室、单负载、单并行拓扑下的观测。
- 风险：把收益当成「通信被消除」会误导后续优化方向——正确表述是「通信被 attention 主链覆盖，仍有约 1.3–1.4 ms residual」。
- 数据缺口：源里未给出 `model_version`，记为 unknown。
