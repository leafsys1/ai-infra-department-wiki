# 单 token 解码的 QKV 拼接改为视图：每步少 384 次拼接 kernel

## Goal

消掉解码每步 384 次 QKV 拼接 kernel：48 层线性注意力（GDN）每步都先调 `rearrange_mixed_qkv` 把 `mixed_qkv` 复制到连续内存再切片，而单 token 时那三块本来就是连续的——让单 token 路径直接返回视图。

## Baseline

- 48 层线性注意力每步都调 `rearrange_mixed_qkv(layer, mixed_qkv)`，把 `mixed_qkv` 复制到一块连续内存后再切片。
- 单 token 时三块本来就是连续的，所以这次拷贝是白做的；C03 基线的匹配八步图诊断里每步目标拼接为 **384**。
- R0043 已把卷积权重布局问题解决，本记录是在同一路径上继续去掉重复的拼接。

## Changed Variable

- 文件：`vllm_ascend/ops/gdn.py`。
- 新增模块级 `_rearrange_mixed_qkv_single_token(layer, mixed_qkv)`：当 `mixed_qkv is not None and mixed_qkv.shape[0] == 1 and mixed_qkv.is_contiguous()` 时，返回 `split` + `view` 产生的视图；否则委托给原来的 `rearrange_mixed_qkv`。
- 同时改写 `AscendGatedDeltaNetAttention` 的 spec 与 non-spec 两处调用点。**+15/−2 行**，叠在 R0043 之上；不改数学，只去掉拷贝。

## Controlled And Uncontrolled Variables

受控：单个 910C/A3 逻辑 die（64 GiB）、TP1·DP1；每条自然 128-token prompt 生成 32 个输出 token、并发 1；每臂两次不计时预热 + 三次独立冒烟；A-B-A-B 四次测量在同一主机、同一负载下按全新顺序执行。

未受控：机制只作用于单 token 解码，prefill 不命中；并发 >1 时快路径不生效。最初一次 NPU 测试失败的原因是 custom-op 引导发生在 device 初始化之后（引导顺序问题），日志已保留，不是本变更的缺陷。

## Procedure

1. 正确性：CPU 检查覆盖 38 个 tensor 用例以及 None/结构检查——精确输出、存储共享、偏移、切分边界与阶梯形状；NPU 检查 split、归一化、循环输出与状态，并比对 token log 概率。
2. 匹配的八步图诊断：对 C03 基线与 C04 候选使用同一套八步解码 graph 诊断做 profile，比较目标拼接、无关拼接与其它 kernel 计数。
3. 一次短 A-B-A-B 筛选（先于冻结判据）。
4. 冻结判据后跑**全新**的 A-B-A-B 确认：每臂 4 条 prompt、32 输出 token、并发 1、两次不计时预热、三次独立冒烟；主指标 TPOT，护栏为 TTFT、总时延、成功率、精确长度一致性与 HBM。

## Results

- 目标内核消失：每步目标拼接 **384 → 0**，保留 **16 个无关拼接**，其余 kernel 计数无变化。
- 正式成对 TPOT 改善：**−0.931715 ms（−3.031684%）** 与 **−0.849822 ms（−2.768119%）**。
- 总时延 **−27.516477 ms / −26.477663 ms**；TTFT **+1.366674 ms / −0.133185 ms**——两个方向相反，**无一致影响**。
- 正确性：16 个请求精确 `128/32` 成功，生成文本与 smoke 输出完全一致；NPU 的 split、归一化、循环输出与状态通过；**token 概率逐位相同**。
- 噪声地板：arm 内 TPOT 标准差 **0.008463–0.019895 ms**；同一变体的漂移 A 为 −0.032237 ms、B 为 +0.049656 ms。
- 筛选观测值（独立证据，不并入正式估计）：TPOT −0.844036 / −0.928689 ms；TTFT −12.776640 / −3.596417 ms，**其有利的 TTFT 均值未被升格为因果结论，也未替代正式结果**。

## Conclusion

单 token 解码时的 QKV 拼接可以安全地换成视图：每步目标拼接 384 → 0，两个成对比较的 TPOT 都下降（−3.031684% / −2.768119%），token 概率逐位相同，因此源轮次裁决 KEEP。

这是**单 token 解码**的机制，**不主张 TTFT 收益**：两个正式 TTFT 变化方向相反（+1.366674 / −0.133185 ms），筛选阶段那个有利的 TTFT 均值也被明确留在筛选观测值里、没有升格为因果结论。收益来自去掉拷贝，而不是新增计算；prefill 与并发 >1 的路径都不命中。

## Applicability And Risks

- 适用：单 token 解码（`mixed_qkv.shape[0] == 1` 且 `is_contiguous()`）的 GDN 路径；不改变数学，只返回视图，回滚成本低。
- 未覆盖（源里原样标为 UNVERIFIED）：通用精度、多模态、投机解码、大规模批处理、端到端多 TP，以及 x86_64 上的可移植性；结论只基于**一个主机、一个负载、两个 A-B 对**。
- 风险：**并发 >1 时门槛不成立**，快路径不生效；把 −3.03% 当成通用解码加速会错。
- 风险：若设备初始化早于 custom-op 引导，NPU 测试会失败——这是环境引导顺序问题，需要先引导 custom ops 再建进程，而不是改本变更。
- 边界：`framework_version` 在源里没有给出，记为 unknown。
