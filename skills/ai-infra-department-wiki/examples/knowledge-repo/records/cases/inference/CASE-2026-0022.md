# DSv4-Flash DSpark 的 draft 长度与 token 预算共用一个池：B/D 两臂的长提示收益

## 目标
32K 提示进单实例 DSv4-Flash W8A8 服务，TTFT 到分钟级。要弄清：这一步到底在等什么，以及
`dspark` 的草稿长度与 token 预算之间是不是在互相抢同一份额度。

## 基线
910C 单机 16 个独立逻辑 die 的单实例：`DP16 · TP1 · EP16`，DeepSeek-V4-Flash W8A8，
`gpu_memory_utilization` 0.88、`block_size` 32、`cudagraph_mode=FULL_DECODE_ONLY`、prefix caching 关闭，
dspark 为 `method=dspark` + `enforce_eager=true`。现役旋钮：`num_speculative_tokens=7`（K7）、
`max_num_seqs=32`、`max_num_batched_tokens=280`。32K 提示、并发 8 时基线 TTFT 约 `133 s`、
吞吐 `55.4 tok/s`。

## 变更变量
本轮**无源码改动、无权重改动**，只改启动参数（旋钮）。两条收益臂：
- **B 臂**：K `7 → 5`（其余不动）。
- **D 臂**：`max_num_batched_tokens` `280 → 560`（K 与 seqs 不动）。
另有对照 C 臂（`max_num_seqs 32 → 16`）用于验证机制，不在本轮 KEEP 内。

## 受控与非受控变量
受控：同一实例、同一模型与权重、同一 util/block-size/cudagraph/prefix-caching 配置、工作点定义
（提示长度、输出长度、并发）、每单元 `FAIL=0`、每次起服做 16/16 rank ready 检查、A 与 B 用时间相邻的
同窗口交错配对（P1/P2 两轮）、逐请求 raw 全部落盘并由独立脚本复算。

未受控：**跨时段漂移**（同代码同权重不同实例的 A 臂会漂，本轮量化并据此只采信同窗口配对）；
宿主 loadavg 在观测窗内 23→55 波动、16 个 rank 与同事容器共存，环境侧原因**未定位**（本轮只量化、
不归因）。

## 执行步骤
1. 先算出预算池账目：引擎按最坏情况预留 `(K−1)×seqs = (7−1)×32 = 192` 个草稿槽位，而预算只有 280
   ⇒ 每步实际可调度 `88` 个 token。
2. 按 A → C → B → D 顺序换臂，每臂完整起服/清场一次，抓取回显确认实测 `max_num_scheduled_tokens`。
3. 每个工作点每臂跑 1–3 个单元（单元 = 一次完整并发批次），主工作点 U2（脚本按 32K 传参、
   实测提示 53,923 tokens、输出 1024、并发 8）用同窗口交错配对。
4. 噪声地板：用同代码重复基线（A1 三个单元 + AR 两个单元、跨 2 个独立起服实例）算 `2×MAD/中位`。
5. 护栏：精度侧另跑 6 seed × 3 重复的 temp=0 token 序列对照，检查逐 token 是否一致。

## 结果
- **预算池账目**（摘录 `S2-budget-mechanism`）：五臂实测 `scheduled` = A `88` / B `152` / C `184` /
  D `368`；KV 容量 A/B/C 均为 `2,196,005` tokens，D 为 `1,910,608`。分块数预测：
  B `ceil(32768/152)=216`（−42.1%）、D `ceil(32768/368)=90`（−75.9%）。
  另有 **B3 臂（K=3）在起服时被引擎拒绝**，原始回显：`DSpark requires num_speculative_tokens >=
  dspark_block_size (5); got 3.` ⇒ 任务单原设计的 K3 在该引擎版本上物理不可执行，实测改用硬约束下的
  最小档 K5。
- **主工作点**（摘录 `S4-paired-chain`，两轮独立配对窗）：B 臂吞吐 `+59.56%`（P1）/ `+60.57%`（P2），
  TTFT `132.60 → 77.60 s`（`−41.5%`）/ `132.89 → 77.17 s`（`−41.9%`），TPOT `−2.92%` / `−2.23%`。
  两窗只差 **1.0pp**；配对窗内 A 自身两单元只差 `0.19%`。
- **D 臂**：同工作点吞吐 `+180.11%`、TTFT `−70.74%`、TPOT `−1.44%`，**代价**是 KV 容量
  `2,196,005 → 1,910,608` tokens（`−13.0%`）、256K 单请求并发倍数 `8.38x → 7.29x`。
- **机制链定量命中**（摘录 `S9-mechanism-quantified`）：B 预测 ΔTTFT `−42.1%` vs 实测 `−41.5%`（配对）/
  `−43.2%`（另一口径）；D 预测 `−75.9%` vs 实测 `−70.8%`（差 5.1pp）。「步数/每步 token」那一段
  **未证实**（`/metrics` 计数器为 16 rank 求和口径，无法与「引擎步数 × 每步 token」模型对齐），
  该段只作臂间相对对照，收益由 TTFT 与吞吐直接观测。
- **噪声地板**（摘录 `S6-noise-floor`）：同代码重复基线 `2×MAD/中位 = 2.37%`；跨时段漂移
  `+1.8% ~ +3.1%`；U1 工作点跨时段漂移 `+50.5%` ⇒ 以旧基线为基准的 U1 数字（B +34.83% / C +47.96% /
  D +43.56%）**不成立、不得引用**；W 工作点噪声 `51%` ⇒ 判不可判定。
- **护栏与代价**（摘录 `S5-other-workpoints`、`S8-boundary`）：短提示 U1（500×并发 8）**不通过**——
  同窗口配对吞吐仅 `+5.09%` 而 ΔTPOT `+11.9%` 超 5% 门槛；EQ 类工作点（2048 提示 / 64 输出 / 并发 1）
  TPOT 退化 `+9.24% ~ +11.05%`（噪声 5.62%），已作为代价写明。
- **精度侧 UNVERIFIED**（摘录 `S7-precision-unverified`）：臂内一致率 `22.2–33.3%`、跨臂
  `16.7–27.8%`，区间完全重叠；基线自身在 6 个 prompt 中有 5 个出现 ≥2 种 token 序列 ⇒ 该判据既不能
  证明输出等效，也不能证明 B/D 引入了输出漂移。
- **原件内部不一致（原样保留）**：源结果文件 §3 表把 D 的 EQ 吞吐记为 `30.08`，独立复算为 `18.77`
  （与两处引用的 `+159.31%` 自洽），本轮采信复算值。

## 结论
**DSpark 的 draft 长度与 `max_num_seqs` / `max_num_batched_tokens` 处在同一个预算池里**：最坏 draft
预留 `(K−1)×seqs=192` 把 280 的预算压到每步只有 `88` 个 token 可调度，长提示因此被切成
`ceil(32768/88)=373` 块，TTFT 由分块数主导。释放预留（K 7→5 ⇒ scheduled 152）或放大预算
（batched 280→560 ⇒ scheduled 368）都能按分块数近线性地降 TTFT：**B 臂在 32K×并发 8 上吞吐
+59.56%/+60.57%、TTFT −41.5%/−41.9%、TPOT −2.92%/−2.23%，且无容量代价；D 臂吞吐 +180.11%、
TTFT −70.74%，代价是 KV 容量 −13.0%。** 两者都远超 `2.37%` 的同代码噪声底线，且两轮独立配对窗
只差 1.0pp。

**边界与未覆盖项**：成立于「910C 单机 16 个独立 die 的单实例 `DP16·TP1·EP16` / DSv4-Flash W8A8 /
util 0.88 / block 32 / prefix caching 关闭 / 当前引擎版本」；**短提示（500 token / 并发 8）不成立**；
EQ 类工作点 TPOT 退化 `+9.24% / +11.05%`（噪声 5.62%）；**精度侧 UNVERIFIED**（判据 1 连基线自身都不满足，无判别力）；
**≥128K 提示工作点、其它 util、其它 block-size、其它部署形态未覆盖**；K 与 seqs 的其它组合未验证；
不含源码改动，未做源码级根因定位。

## 适用范围与风险
适用于长提示主导、单实例多 die 的 DSv4-Flash W8A8 部署。风险四条：一是 **D 臂不是免费的**——
KV 容量掉 13.0%，长上下文并发倍数从 8.38x 降到 7.29x，容量敏感场景要按这个代价取舍；二是
**别把结论外推到短提示**（+5.09% 且 TPOT 退化 +11.9%）；三是**必须同窗口配对**，跨时段比较会把
漂移（U1 上达 +50%）读成收益；四是**精度没有结论**，不能声称输出等效，也不能声称退化。
