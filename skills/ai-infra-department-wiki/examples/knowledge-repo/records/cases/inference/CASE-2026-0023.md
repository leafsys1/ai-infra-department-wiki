# Qwen3.8-27B GDN chunked-prefill metadata 的 exact-shape 缓存：机制命中成立、端到端收益落在噪声内

## 目标
GDN 的 chunked-prefill 路径每步都要重建 metadata 并做一次 H2D。这些 metadata 在形状重复时会
完全相同——那么给它加一层 exact-shape 缓存，**命中是否真的发生、复用是否真的安全、端到端是否真的
变快**？三问分开回答。

## 基线
aarch64 / Ascend 910B3 单机 8 die，本次实例 `TP4 · DP1`、可见 4 die；Qwen3.8-27B W8A8
（`quantization=ascend`）；`max-model-len=36864`、`max-num-batched-tokens=8192`、`max-num-seqs=8`、
`gpu-memory-utilization=0.80`。基线臂 = 缓存关闭（`T0246_CACHE=0`），走原始构建路径。

## 变更变量
唯一干预：在 GDN metadata 构建函数 `_build_non_spec_chunked_prefill_metadata` 上加一层
**exact-shape metadata cache**（追加式 overlay 补丁，key 覆盖 device/布局/dtype/shape/stride/n_seqs/
`cu_seqlens` 全值/配置指纹；命中即复用、miss 走原路径），由环境变量 `T0246_CACHE=1` 切到干预臂。
**未改** token IDs、权重、量化口径、服务拓扑、启动参数、其它算子。

## 受控与非受控变量
受控：同一实例、同一源码树、同一 checkpoint、同一启动参数、同一工作点定义、每格每臂 3 个有效重复、
每重复 8 条请求（`nreq=8 / ok=8 / failed=0 / rejected=0`）、两臂之间完整清理、收工后还原 pristine 并
核对文件哈希（pristine `gdn_attn_builder.py` sha256 `8693637198ea572dbf5a1c14b5d220c512bb0483c8beaeaf5c73f8653ba5544f`，
打补丁后 overlay sha256 `4f7006f5f47295ebb5ff434030f725257966e9b04071c33c2acb58e1ea091f53`）。

未受控：本实例自身的随机抖动（用臂内离散度量化，见 Results）；**基线自身的逐 token 可复现性**——
实测就不复现，导致预注册的逐 token exact 判据不可评估。

## 执行步骤
1. 逐 rank 埋点统计 builder 调用数、cache miss/hit、每次 miss 的 `prepare_chunk` 与 H2D 次数、
   每次 hit 的对应次数。
2. 对命中复用的对象做**逐元素验证**：比对 11 个 metadata 字段，记录 `identical` 布尔。
3. 端到端：`32K`（32760 token）提示 × 并发 `c1`/`c8`、输出 1024 token、每格每臂 3 个有效重复。
4. 噪声地板：用两臂各自的臂内离散度 `2×MAD/中位` 给出。
5. 护栏：预注册含「逐 token exact」——在**基线自身**上先检查该判据是否可评估。

## 结果
- **机制计数**（摘录 `S2-mechanism-counts`）：4 rank 合计 `6012 hit / 60 miss`，命中率 **`99.01%`**；
  每次 miss 恒为 `6 prepare_chunk + 6 H2D`，每次 hit 恒为 `0 / 0`；`188/188` 条逐元素验证记录中
  11 个 metadata 字段**全部一致**、`identical:false` 计数为 `0`；miss 总耗时 `3,396,714 us`、
  hit 总耗时 `577,514 us`（4 rank 合计）。
- **命中集中度**：1503 次命中里 `1208` 次（`80.4%`）落在同一个 `cu_seqlens = [0, 2048]` 的 key 上；
  15 个 miss key **两两不同**，未观察到跨形状误命中。缓存容量上限（64）在本次工作点上未触顶。
- **端到端**（摘录 `S3-endtoend`）：`32K/c1` TTFT 中位 `6733.1 → 6803.8 ms`（**`+1.05%`**）；
  `32K/c8` `20617.7 → 20438.0 ms`（**`−0.87%`**）。同口径 TPOT `+0.44%` / `−0.02%`、
  吞吐 `−0.11%` / `+0.28%`。
- **噪声地板**（摘录 `S4-noise`）：`32K/c1` 臂内 spread 为 baseline `1.56%` / intervention `0.72%`；
  `32K/c8` 为 `0.54%` / `1.46%` ⇒ 噪声区间约 **`0.54%–1.56%`**。上述两处差异**都落在区间之内**，
  且方向相反（一处变慢、一处变快），是典型随机噪声形状。
- **逐 token exact 不可评估**（摘录 `S5-token-exact-unevaluable`）：**基线自身**同 prompt 三次重复
  出现 **2–3 种不同的 token 序列** ⇒ 该判据在本实例上没有判别力，既不写候选 `PASS` 也不写候选 `FAIL`。
  这是**显式保留的缺口**，不是被绕过的判据。

## 结论
**exact-shape metadata cache 在真实 Qwen3.8-27B W8A8 路径上「机制命中」成立**：命中率 99.01%，
miss 路径恒为 6 次构造 + 6 次 H2D、hit 路径恒为 0/0，复用对象在 188/188 条验证中对 11 个字段逐元素
一致，且无误命中。**但端到端性能收益 UNVERIFIED**：`32K/c1 +1.05%` 与 `32K/c8 −0.87%` 方向相反、
均落在 `0.54%–1.56%` 的臂内噪声内，因此本轮**不产出端到端收益、不计为收益型轮次**，也**不得**把
`−0.87%` 写成收益。

**边界与未覆盖项**：成立于「aarch64 / Ascend 910B3 / `TP4 · DP1` / Qwen3.8-27B W8A8 /
`max-model-len=36864`、`max-num-batched-tokens=8192`、`max-num-seqs=8`、`util=0.80` / 本次镜像」；
**未覆盖**其它 TP/DP 形态、其它 `max-num-seqs`、≥64K 提示、其它量化口径或其它模型。未做源码级根因
定位（为何基线在 temp=0 下不可复现）、未做 key 分布建模、未验证多轮长跑下的缓存淘汰收益。

## 适用范围与风险
适用于「形状重复、metadata 重建成本可观测」的 chunked-prefill 路径。风险与用法三条：
一是**机制命中 ≠ 端到端收益**——命中率 99.01% 也不代表吞吐会动，本轮的端到端数字全在噪声里，
报收益前必须先量噪声地板；二是**缓存正确性必须逐元素验证**（本轮 188/188 是它敢上线的唯一依据），
key 少一个维度就会静默错用 metadata；三是**别把逐 token exact 当作通用护栏**——本实例上基线自身
就不复现，该判据在这里无判别力。
