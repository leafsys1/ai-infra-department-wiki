# DSv4-Flash 单实例 prefix caching 命中链不可用：同串重复请求命中恒为 0

## 目标
一个必答的机制问题：开了 prefix caching 之后，**同一条 prompt 再发一次，到底有没有命中缓存**？
在把任何「前缀缓存收益」写进结论之前，先确认这条链真的通。

## 基线
910C 单机 16 die、DeepSeek-V4-Flash W8A8、单实例 arm B（`--enable-prefix-caching`）；
budget 280、seqs 32、util 0.88、block-size 32；**单一 API 实例（同一服务端口）**。
每条请求 HTTP 200、512 prompt tokens、输出 16 token。本轮**无性能测量**，是机制存在性取证。

## 变更变量
没有改代码、没有改参数。被操作的自变量只有一个：**请求序列**——在同实例同端口上连发逐字节相同的
512-token prompt（P1 连发两次），另加一条不同串作对照（P2）、以及一组独立重复（P3 连发两次）。
判据在**执行前冻结**。

## 受控与非受控变量
受控：同一 API 实例、同一端口、同一 engine label、prompt 逐字节相同（记录完整 prompt SHA-256）、
每条请求前后读取同一 engine 的累计计数器、每条请求的 prompt token 数与 HTTP 状态。

未受控：**部署拓扑**本轮未做对照取证（16 个 rank 各自独立 KV、端口间不共享），后由后续任务回填；
**根因**未定位，本轮不做任何推断。

## 执行步骤
1. 对每条请求，在发送**前后**读同一 engine 的三个累计计数器：
   `prefix_cache_queries`、`prefix_cache_hits`、`prompt_tokens_cached`，取 pre→post 增量。
2. 用查询数增量证明「前缀缓存查询路径确实被调用」；用命中数与缓存 token 数增量证明
   「匹配与复用是否发生」。
3. 按执行前冻结的四分支判据判决，并做一组独立重复（P3×2）。
4. **不用端到端耗时做机制判据**。

## 结果
- **逐请求增量**（摘录 `S2-request-table`，5 条请求）：R1/P1、R2/P1、R3/P2、R4/P3、R5/P3 全部
  `Δprefix_cache_queries = +512`、`Δprefix_cache_hits = 0`、`Δprompt_tokens_cached = 0`，全部 HTTP 200。
  其中 P1 的两条请求 prompt SHA-256 完全相同（`e2cd1673…88f91`），P3 的两条也完全相同
  （`6422a667…f3edfd`）。
- **判据命中**（摘录 `S3-verdict-criteria`）：本轮命中第 2 行分支——
  `Δhits(R2) = 0` 且 `Δqueries(R2) ≈ |P1|` ⇒ 记「机制不可用」**硬否证**，阻断点未定位处写 UNVERIFIED，
  **不臆测根因**。（若为 `Δqueries ≈ 0`，则应判「取证口径未命中、不算否证」——本轮不是这种情况。）
- **独立重复**：P3×2 同样为查询 512、命中 0、缓存 token 0，未见偶发命中。
- **噪声地板**：本轮不测性能，没有效应量/噪声地板；命中计数是 0 的**存在性判据**，
  **不把它写成性能退化比例**。
- **护栏**：无 `FAIL`、无非 200 请求；每条请求的 prompt 长度与输出长度均按口径精确。

## 结论
**在本口径内（同一 API 实例、同一端口、512-token 全整块 prompt、arm B 参数），DSv4-Flash 单实例的
prefix caching 命中链不可用**：查询数按整串长度增加（+512）说明查询路径确实进入，而命中数与缓存
token 数恒为 0；独立重复给出同样结果。因此「前缀缓存的端到端收益」在本口径内**不可得**，该轮按冻结
判据归档为 REVERT（B44 机制硬否证），**不产出优化项**。

**边界与未覆盖项**：成立于「同一实例同一端口 / 512-token 全整块（16×32）prompt / budget 280、
seqs 32、util 0.88」；**未覆盖**其它 block-size、更长 prompt、其它 util。部署拓扑这条替代解释
已由后续任务回填排除（确证为 16 个独立实例，且两次请求固定同一端口/同一 engine，因此跨 rank 不共享
**不能**解释本次同实例 `Δhits=0`）。**根因未定位（UNVERIFIED）**：为何 arm B 下同实例同串不命中
（DP 分组是否禁用本地 block 复用 / hash key 是否含 rank 维度），本轮无证据，**不得臆测**。

## 适用范围与风险
适用于「准备启用 prefix caching 或准备引用其收益」的场景。风险三条：一是**先证链通、再谈收益**——
查询路径被调用（Δqueries=512）不代表命中发生（Δhits=0），两者必须分开看；二是**别把命中为 0 写成
性能退化**，本轮没有性能测量；三是**别在这里编根因**——本轮只给否证与边界，归因留待有证据的后续轮次。
