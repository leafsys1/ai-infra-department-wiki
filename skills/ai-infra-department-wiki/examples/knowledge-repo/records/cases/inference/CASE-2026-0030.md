# R0007 DSA-CP drafting metadata 跨 KV-cache group 复用：局部 −27.7% 但同会话正式吞吐 −5.67%/−6.47% → REVERT

## 目标
回答一个问题：把 DSA-CP draft 阶段的 attention metadata 在多个 draft KV-cache group 之间复用
（上游 #14916），能否在**正式负载**上转成端到端收益。若能则保留候选代码，若不能则回退。

## 基线
未 backport 的 `share=0` 路径，同会话、同拓扑、同负载。部署为 8×910B3、DP2×TP4(EP8)、
`--max-model-len 1048576`、DSpark K=7、`enable_dsa_cp=true`、batched-tokens 8192。正式负载为
32768 输入 / 1024 输出 / 48 请求 / 并发 12 / rr 0.9 / DP2。

## 变更变量
手工 backport 上游 `a25f98fbb9`（#14916，"Cache group-invariant DSA-CP drafting metadata across
kv-cache groups"），运行时开关由 `share=0` 切到 `share=1`。臂序为 B（0）→ C1（1）→ C2（1），
结束时置回 0。改动落在 `framework/vllm` 与 `framework/vllm-ascend` 两个文件。

## 受控与非受控变量
受控：同一会话、同一拓扑（DP2×TP4/EP8）、同一 K=7、同一 workload 与采样/缓存协议；未 reset NPU、
未全局 kill 进程；未覆盖与本轮无关的既有修改。

未受控：跨会话机器状态漂移——本轮 baseline 臂（511.9868 tok/s、TPOT 19.1 ms）比冻结 v2 基线
（468.9507、21.1 ms）快 9.2%，所以**只有同会话 B vs C1/C2 可用于候选判定**。运行时开关语义未逐
step 取证（`share=1` 时第二个 group 是否真的读到 cache）。同配置三次测量最大互差 30.2%。

## 执行步骤
1. 执行前先冻结判据（TASK §5）：CONTINUE 要求 ① 完整 period/ITL 中位改善 ≥5%、② 至少两个独立
   candidate 重复块同方向、③ `temperature=0` 输出逐字等价、④ 无错误。
2. 先确认命中前提：归档的 28,692 条探针记录全部 `n_groups = 2`、`gids = [2, 3]`，即该 draft step
   真实存在 2 个 draft KV-cache group，本轮不是 `NOT_APPLICABLE`。
3. 三层观测：① 局部 `build_draft_attn_metadata` 的 `loop_ms` 插桩；② 短链路 decode ITL（同会话
   单请求流式）；③ 正式 48×1024 吞吐。
4. 臂序 B（share=0）→ C1（share=1）→ C2（share=1）交替测量，收尾置回 0。

## 结果
- 局部 `loop_ms` 中位：6.5072 ms（n=9,208）→ 4.7063 ms（n=19,484），**−27.7%**（现场臂口径
  6.3605→4.3011 ms，约 −32%）。
- 短链路 decode ITL：66.0987 / 66.4439 ms → 61.8218 / 61.9442 ms，**−6.47% / −6.77%**。
- 正式 48×1024 吞吐：511.9868 → **482.9757（−5.67%）/ 478.8370（−6.47%）** tok/s，TPOT 19.1 →
  22.2 / 20.2 ms。两次重复**同时退化**。
- 插桩成本已排除为 B/C 差异来源：两臂都写 JSONL（`share=0` 9,208 条、`share=1` 19,484 条）。
- 回退：`framework/vllm-ascend` 与 `framework/vllm` 均回到本轮前 commit（`f2f74a16c` / `568afb3`），
  `git status --short` 为空；只读复核确认 `framework/vllm-ascend` 全仓已无 `draft_for_drafting` /
  `R0007` / `r07` 任何字符串。

## 结论
**没过的闸**：判据 ①② 在**短链路**上满足（两处独立测量、同方向、−6.5% 量级），但正式负载给出了
**相反**的结论——两次重复的吞吐同时退化 5.67% / 6.47%。按 TASK §5，"本地改善未转成端到端收益"
即 REVERT，不保留候选代码。补强证据：即使两处测量都按最有利方式取值，局部节省的 per-token 上限
也只有约 **2.9%**，低于 CONTINUE 要求的 ≥5%。

**未覆盖项（原样保留）**：① 局部改善为何没有（甚至反向）传导到端到端——机制未知；② 本轮正式运行
超出合同授权范围（`current/TASK.md` §5/§6 明文禁止跑正式 48×1024，仓库内无授权修订记录）；③ 逐字
输出等价性未验证（判据 ③ 无证据，弱证据为 48/48 成功、0 失败、prefix 命中率 87.28%）；④ 候选 diff
未归档，"实现是否严格符合 TASK §2 边界"不可事后复核；⑤ 单次不可判定（同配置三次测量最大互差
30.2%）；⑥ 收尾时在线进程仍是插桩会话。

## 适用范围与风险
适用于 DSA-CP + DSpark spec-decode + `max_model_len=1048576` 的 8×910B3 DP2×TP4(EP8) 部署。
**不适用**：不能把"局部 loop_ms −27.7%"外推为端到端收益，也不能推广到其它拓扑、精度或模型。
主要风险是口径混淆——短链路 ITL 与正式吞吐可以反向，且跨会话绝对值不可比（本轮 baseline 本身比
冻结基线快 9.2%）。若未来重开此机制，必须先解决"退化机制未查明"这一点，并按同会话配对口径判定。
