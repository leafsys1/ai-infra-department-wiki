# R0050 KV 池后端 mooncake→memcache+device_rdma：主指标 −48.497% 达标但每臂 5 单元未达 → 收益 UNVERIFIED

## Goal

把 R0049 的一次观测（换池后端后 TTFT 从 4.63 s 掉到 2.15 s）推进成**可验收的收益结论**：交错配对
+ 多单元 + 执行前把判据写死，让"处理臂更好"必须在噪声地板上跨过去。

## Baseline

armA：池后端 `mooncake`。部署为 910C/A3 × 2 机、每机 16 个逻辑 die、PD 分离（P 16 rank / D 16 rank）、
DP16 · TP1 · EP16，模型 DeepSeek-V4-Flash-0731 W8A8。负载为 32K 共享前缀输入（客户端
`prompt_tokens=32851` / 引擎侧 `32850`）、输出 1024、48 条/单元、并发 10、rr 0.9。

## Changed Variable

armB：把池后端由 `mooncake` 换成 `memcache` + `device_rdma`。其余（模型、拓扑、负载、单元定义）
两臂相同。

## Controlled And Uncontrolled Variables

受控：同一对机器、同一模型与拓扑、同一冻结负载；**交错配对**序列 A1 B1 A2 B2 A3 B3 A4 B4 A5；
单元定义固定（完整重启服务 + 健康检查 + 预热 4 条 + 测量 48 条 + 取证）。

未受控：绝对值带 DEBUG 观测开销，**只作相对比较**；冷/热占比来自 bench 合成模式且窗口语义未取证；
48/432 条未收集服务端关联（成本取舍）。

## Procedure

1. 执行前写定判据：主指标 TTFT p95（单元中位）相对变化 <−3% **且**绝对值 > 2×pooledMAD/baseline；
   护栏 TPOT p95 退化 ≤5%、FAIL=0、E2E 不退化；两臂交错、臂内 5 个单元。
2. 按 A1 B1 A2 B2 A3 B3 A4 B4 A5 执行，每个单元完整重启 + 预热 + 48 条测量。
3. 失败重试按预注册上限执行（第 5 单元的最后一次现场尝试已用尽）。

## Results

- 主指标：TTFT p95 **单元中位 4.67772 s → 2.40917 s（−48.497%）**；pooled MAD **0.11270 s =
  基线 2.409%**；预注册阈值 **4.818%** → 「>3% 且 >2×pooled MAD」两条同时满足。整体 TTFT 均值
  2.10536 → 1.62395 s（−22.87%）。
- 护栏：TPOT p95 **−1.34%**、E2E p95 **−9.64%**、输出吞吐 396.32 → 409.96 tok/s、**FAIL 0/432**、
  9/9 单元路由关联 48/48。
- 逐单元：armA A1–A5 的 ttft_p95 为 4.3665 / 4.6777 / 5.0190 / 4.6990 / 3.9038 s；armB B1–B4 为
  2.3619 / 2.4564 / 2.1728 / 2.5219 s。臂内波动 armA MAD 0.31119（6.65%）明显大于 armB MAD
  0.07996（3.32%），主判据取单元中位正是为此。
- 机器复算件与主控裁决并存：`analysis-n9-machine-verdict.txt` 输出 `VERDICT: 收益验收成立`
  （其判据集合里**没有**「每臂 ≥5 单元」这一条），而同一份输出里 `units_per_arm` 为
  `{"armA": 5, "armB": 4}`；主控按预注册协议判 **UNVERIFIED**。两文件并存、不改写任一方。

## Conclusion

**没过的闸**：「每臂 5 个有效单元」未达——armB 第 5 单元在 5 次尝试中全部挂起（0/48、0/48、1/48、
10/48、1/48），因此处理臂数字**建立在选择性成功子集上**。第二条护栏也不成立：**稳定性回退成立**
（armA 7 次启动 0 次池/服务侧失败，2 次无效启动为工具 bug、未进入测量；armB 10 次单元执行 **6 次
失败** = 测量阶段 5 次 + 预热阶段 1 次）。故障取证显示池 rank 注册缺失与 `device_rdma` 传输错误共现
（`WaitFeatures ... error code -1`、`RaSendWrV2 failed, ret: 128103`、`ReceiveCqe failed! ret:-1`），
但池自身计数器未报错、失败现场池容量 248 GiB / 已分配 344 MiB 且无容量类错误 → **不支持「简单容量
耗尽」解释**，映射与因果**未闭合 → 归因不明**。Decision = **CONTINUE**（留待另立轮次，不表示继续做
第三次同口径补测）。

**未覆盖项（原样保留）**：冷/热分层信号**仅作信号、不称完整 KEEP**（冷态 TTFT 均值 −46.01%、冷态
p95 单元中位 −50.64%，但占比是合成模式、窗口语义未取证）；热态**不写成已成立**（分箱内样本少）；
本轮**不是**「memcache 更快」的结论，也**不是**「memcache 不能用」的结论（机制层既未被否定也未被
定位）；未产出任何性能收益声明、池 miss 行为、profiling 证据、跨集群/多租户行为、armB 第 5 单元的
有效数据。

## Applicability And Risks

适用于"高波动、有噪声地板、需要预注册判据"的端到端收益验收，也适用于任何"处理臂数字来自选择性成功
子集"的场景。主要风险：机器复算脚本的判据集合可能与预注册协议不一致（本例输出"成立"而主控判
UNVERIFIED），**必须以预注册协议为准**，且不得把"进仓的数字"当收益结论。要把 −48.5% 变成可验收
收益，至少需要：先把 armB 单元级挂起压住（池侧注册/传输路径的可观测判据 + 恢复动作）做到两臂各 5 个
有效单元；关掉 DEBUG 按同口径重做配对；补齐服务端关联核验的缺失条目。
