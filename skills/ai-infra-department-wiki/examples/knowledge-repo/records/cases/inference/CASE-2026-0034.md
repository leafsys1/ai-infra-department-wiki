# R0055 显式 compile 范围被静默丢弃 + iteration_tokens_total 指标语义闭证

## Goal

闭证两件事，为后续干预设计与指标解读立地基：① 用"显式固定 compile 范围"隔离出纯调度收益的干预设计
**在源码层是否成立**；② `vllm:iteration_tokens_total` 的每次观测到底是**什么粒度**（能不能当分块
prefill 步数用）。

## Baseline

`deepseek-v4-flash-w8a8`；910C 单机 16 die 单实例不分 P/D（`DP16 · TP1 · EP16`）。引擎为容器内
vLLM 0.26.0 + vllm-ascend（镜像 `nightly-releases-v0.26.0rc-a3`）。被对照的上游结论来自 R0054，
其数字与验收状态（UNVERIFIED）**不被本轮改写**。

## Changed Variable

**无代码改动。** 本轮是只读取证 + 机器复算：读容器内 `vllm/config/vllm.py`、
`vllm/config/compilation.py`、`vllm_ascend/ascend_config.py`；对 5 次起服的"用户入参 → 生效值"做只读
回显；对 11 个单元的请求级指标做恒等式复算。

## Controlled And Uncontrolled Variables

受控：同一容器镜像与同一引擎版本；同一套请求；11 个单元两臂同套请求。
未受控：**沙箱缺口（非证据缺口）**——本地不存在 vllm-core 源码（`find` 全 0 命中），主体 1 的判决点
只能由容器内只读取证闭合；两条结论来自不同任务单，本轮只引用、不重测；B 臂首条请求（预热）解码异常
原因未查（不在本轮范围）。

## Procedure

1. 主体 1：读 `vllm/config/vllm.py` 中 `compile_ranges_endpoints` 的取值链与守卫，判定显式端点会不会
   被覆盖；再用 5 次起服的运行期回显佐证"入参 → 生效值"。
2. 主体 2：先查指标更新点（首轮核对时 **MISSING**），再用请求级指标做恒等式复算：
   `iter_tokens_sum Δ == prompt Δ + generation Δ`，并对照 `iterations Δ`、请求级 `prefill_cnt Δ`、
   `(2048,4096]` 桶增量。
3. 记录只读对象的 sha256（`vllm/config/vllm.py` = `d4c31282c664c91bee81267a2134a9609d16c33e88cc40e0f020256346510a87`、
   `vllm/config/compilation.py` = `267f4ca04fdcd2f0cf55c334782dd498c8051b9500ad088673d79518fc712db0`、
   `vllm_ascend/ascend_config.py` = `adc7f68ddbb2cb2b20e5e7c310225d901c01f7edc71c1698d6f4fd01b1e134b4`）。

## Results

主体 1：显式端点是**追加**进候选集合（不是替换），但**先过守卫**
`if compile_range_end is not None and x < compile_range_end and x > 1`（2006–2014 行），而
`compile_range_end = self.scheduler_config.max_num_batched_tokens`（1913–1914 行）。本部署候选值
**全部 ≥** `max_num_batched_tokens` ⇒ 守卫全部筛掉，显式项被**静默丢弃**，生效端点 100% 来自派生值。
运行期只读佐证（5 次起服的「入参 → 生效值」，左值恒 `None`）：`[560] / [1120] / [560] / [1120] / [280]`。
（**原样保留的口径差异**：README.md §2.2 把守卫行号写作 2010 行，RESULT.md 写 2006–2014 行；同事实
两种写法，不自行裁齐。）

主体 2：更新点在首轮核对时 **MISSING**（本地机械事实：11/11 单元的请求级 `prefill_cnt Δ` 恒为 1，而
同一单元 `iterations Δ` 为 18~46 ⇒ 二者不同粒度）；随后闭合为：每次观测 = **一个引擎步**（one set of
`EngineCoreOutputs`）内 `prompt_token_stats.computed + num_generation_tokens`，其中 prefill 项按请求
**一次性**计入"该请求本地真实计算的 prompt token 总数"
（`num_computed_tokens = num_prompt_tokens - num_cached_tokens`），**不是本次 chunk**。

机器复算（11 个单元，两臂同套请求）：单元数 = 11；恒等式 `iter_tokens_sum Δ == prompt Δ + generation Δ`
**11/11 成立**；`iterations Δ` 区间 = [18, 46]，同一单元 `prompt Δ` 恒 3072（恢复验证单元 2048）、
`generation Δ` 恒 128；`(2048,4096]` 桶增量恒为 1 的单元 11/11 ⇒ 3072-token 请求在该桶只留 1 次
观测，与 `iterations Δ`（18~46）不是同一粒度；请求级 prefill 计数 Δ=1 的单元 11/11。逐单元样例：
A_u01 `iterations Δ=19` / `iter_sum Δ=3200`；B_u02 `20 / 3200`；B_warm1 `46 / 3200`；R_restore_check
`19 / 2176`（prompt Δ=2048）。

## Conclusion

**没过的闸**：主体 1 的事前判据「显式范围不被覆盖」**不满足** ⇒ 该干预设计**不成立**（入参写 `None`
与写一个 ≥ 预算的值，生效结果完全相同）。主体 2 则**撤回** R0054 中「分块调度步数减少」这处**强因果
措辞**——桶计数不能当分块 prefill 步数。

`Decision` = **REVERT**。这里的 REVERT = 「干预设计在源码层不成立 + 一处强因果措辞被撤回」，
**不是**端到端性能退化、**也不是**「证明 `batched` 无收益」；R0054 的数字与验收状态（UNVERIFIED）
**不被本轮改写**。**未产出**：任何 OPT 收益、任何 KEEP 结论、任何新的性能阈值或性能测量。

**原样保留的异常与缺口**：① B 臂每次启动后首条请求（预热）解码异常（`iterations=46`，其中约 20 步只
调度 1 个 token、平均输出间隔 16.1~16.2 ms），正式单元稳定在 6.04~6.43 ms；按 protocol 不计入判据，
原因未查；② 沙箱缺口——本地无 vllm-core 源码，主体 1 只能由容器内只读取证闭合；③ 任务单指定的对照
现场非本轮主体——B 臂前缀缓存链路被真实调用但零命中
（`vllm:prefix_cache_queries_total=9216` / `vllm:prefix_cache_hits_total=0`），该现场属另一个候选方向，
本轮**不据此下任何结论**。

## Applicability And Risks

适用于两类判断：① 任何"想用显式参数隔离某个机制"的干预设计，先核对源码里的**守卫与优先级**，别假设
入参会生效；② 任何用直方图桶计数推断步数的解读，先确认指标的**观测粒度**。**不能读**：不能把"桶计数
为 1"解释成"只发生了一次分块 prefill 步"；不能把主体 1 的守卫行为外推到其它版本（换版本须重新核对
行号与守卫）。风险点：本轮的判决点依赖容器内只读取证，若镜像或源码快照变化，需重做取证。
