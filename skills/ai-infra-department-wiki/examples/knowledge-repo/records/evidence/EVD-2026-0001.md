# bash -n 门禁在错误引号写法上失败、在修正写法上通过的实测输出

## Collection Method

在仓库内的 `artifacts/2026-09-23-runsh-quoting-repro/` 下放置两个最小片段，对二者执行 `bash -n`。
该目录同时保留 `bad.sh`、`good.sh` 原文，任何人可重新执行得到相同结论。

## Command

```bash
cd artifacts/2026-09-23-runsh-quoting-repro
bash -n bad.sh ; echo exit=$?
bash -n good.sh ; echo exit=$?
```

## Relevant Output

```
## bad.sh
bad.sh: line 7: syntax error near unexpected token `)'
bad.sh: line 7: `docker run --rm -v ./models:/w "${IMAGE}" bash -lc 'python3 -c "import os; print(os.environ[\'MODEL_REPO\'])"''
exit=2

## good.sh
exit=0
```

## Interpretation

`bad.sh` 的整文件语法在解析阶段即失败（exit=2），不是运行时才报错，因此该交付脚本在任何机器上都
无法启动。`good.sh` 通过解析。证据支持“生成脚本后必须执行 `bash -n` 门禁”，不支持任何性能结论。
