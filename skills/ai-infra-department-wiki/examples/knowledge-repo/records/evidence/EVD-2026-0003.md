# 看板分发与 HTTP 访问通路的实测输出

## 采集方法
在一台具备网络与容器运行时、但未安装浏览器的服务器上，对“安装 → 构建 → HTTP 访问 → 渲染”整条
通路逐段取证。看板渲染使用 DOM 桩执行页面真实内联脚本（本机无 Chromium，未做跨浏览器矩阵）。

## 命令
```bash
bash <server>/check-dashboard.sh          # 生成本日志
python3 <server>/check_dashboard_render.py
```

## 相关输出
见本记录 `locator` 指向的日志文件，含：安装产物文件数与看板摘要、`build` 是否把看板放到 catalog
同目录、各路径 HTTP 状态码、DOM 桩渲染的节点数与 catalog 记录数是否一致、以及校验健康状态。

## 解释
证据支持：看板确实随 Skill 分发、`build` 确实把它放到数据旁、页面确实渲染了服务端提供的记录
（而不是内置演示数据），且图谱关系数与 `generated/graph-data.json` 一致（取证时为 14 节点 / 16 关系；
语料增长后计数变化，该检查可重跑）。
访问控制当前在 `config.json` 中关闭（内网试点，匿名 200），点文件与路径穿越仍为 404；
若端口超出可信网段，必须恢复鉴权并加 TLS。证据不支持任何性能或模型质量结论。
