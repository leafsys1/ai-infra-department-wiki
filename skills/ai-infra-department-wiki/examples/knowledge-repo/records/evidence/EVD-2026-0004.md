# 看板字段契约检查的冻结输出：页面读取的字段名与产物实际字段的比对

## 采集方法
在一台没有安装浏览器的服务器上，把页面的内联脚本放进 DOM 桩里执行，喂服务端实际提供的
`catalog.json` 与 `graph-data.json`；同时从页面脚本里抽出它读取的记录字段名，与产物记录的字段集合
求差集。检查分为四段：字段名比对、关系存放位置、渲染计数与产物计数比对、以及卡片文案抽样。

## 命令
```bash
python3 <server>/check_field_contract.py --refresh      # 生成本日志
python3 <server>/check_dashboard_render.py              # 第 3 段引用的渲染检查
node <server>/tools/card_probe.cjs                      # 第 4 段引用的卡片抽样
```

## 相关输出
见本记录 `locator` 指向的日志文件，含：

- 页面读取的记录字段名与产物字段集合的差集（`read_by_page_but_absent_from_catalog`）；
- `catalog_has_edges_key=False` 与 `catalog_edges=0` / `graph_data_edges=16` 的对照，以及
  `graph-data.json` 的边字段名 `from` / `to` / `relation_type`；
- DOM 桩渲染的 `records_listed` / `graph_nodes` / `graph_edges` 与产物计数的逐项对照；
- 卡片抽样中显示“未分类”的卡片数。

## 解释
证据支持两件事。第一，缺陷是真实的且可复现：页面读的是 `catalog.edges`，而该键不存在，关系在
`graph-data.json` 里，所以只读 catalog 的图谱必然画出 0 条关系——日志把“页面读的键”和“产物有的
键”并排列出，这一点不依赖叙述。第二，修复后的渲染与产物一致（取证时语料）：14/14 条记录、16/16 条关系、
0 张卡片显示占位文案，页面读取的字段名全部存在于产物中。

证据不支持任何性能或模型质量结论；本机无浏览器，渲染由 DOM 桩执行页面真实内联脚本得到，
未做跨浏览器矩阵。
