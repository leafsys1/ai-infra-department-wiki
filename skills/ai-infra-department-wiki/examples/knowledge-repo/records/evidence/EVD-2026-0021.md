# R0048 同 4 die 上 1×TP4 与 4×TP1 副本的形态对比实测输出

## 采集方法
上游轮次 R0048 在同一节点、同一源码（R0044 overlay）、同一 checkpoint、同一四个逻辑 die 上，
一次会话内顺序执行三个 arm：`tp4`（一个实例占用 4 个 die）→ `rep4`（四个 TP1 实例，每实例一个 die，
每实例承载一条流）→ 再复测一次 `tp4` 以框定漂移。四条固定自然 128-token prompt 按 round-robin
打到所请求的并发度，32 个输出 token，temperature 0，seed 1024，`ignore_eos`，两级并发都有不计时
预热，每级两轮计时，每请求一次尝试。各 arm 的启动 flags 除 TP 度、可见设备与端口外完全相同。
门槛为「完成且 token 数精确、无 OOM/重启」；输出一致性不作门槛。

## 相关输出
见 `locator` 指向的冻结摘录。含：两形态的聚合吞吐 / 单流 TPOT / 单流 TTFT 与比值（1.095 / 0.650 /
2.169）；单路（1 个用户）时 TP4 42.47–45.31 tok/s、TPOT 15.84–16.73 ms，对比单副本 27.40 tok/s、
31.55 ms；每步权重读取账目（B 方案 4×28.4 GB ≈ 113.7 GB vs A 方案 28.4 GB）；预注册预测
（TP4 ≈247、副本 ≈133）与实测（118–123、108）的对照；TP4 批 1→批 4 的单步 15.88 → 20.43 ms
（+28.7%）与每 token 成本 3.11 倍；跨会话漂移（22:53 UTC 45.31 → 03:35 UTC 42.47 tok/s，−6.3%）；
副本共置代价 +4.9%（29.97 → 31.42 ms）；两轮重复性 ≤0.4%、每 arm 每级 18/18 请求 token 数精确；
副本臂前 4 次起服失败各自留 `ATTEMPT_FAILED.md` 且不计入测量。

## 解释
证据支持：**在同样四个逻辑 die、四条并发流、短提示短输出（128 in / 32 out）的负载下，1×TP4 实例在
聚合吞吐（1.095×）与单流 TPOT（0.650×）上优于 4×TP1 副本，而副本在首 token 上快 2.17×**
（201.1 ms vs 436.2 ms，原因是 TP4 把四条 prefill 排进同一引擎、彼此等待）。同时支持「批处理几乎免费」
这一前提不成立：TP4 从批 1 到批 4 每步成本 +28.7%，每 token 成本只降到 3.11 倍。跨会话漂移（6.3%）
被如实记录，且排序结论对两次 TP4 测量分别成立。

证据**不支持**：>4 路流、>4 副本、长上下文（prefill 占比不同）下的形态排序；真实多租户排队与故障
隔离行为（本轮未测，只有形态性能）；两形态之间的精度差异（本轮只校验 token 数与时间）。
