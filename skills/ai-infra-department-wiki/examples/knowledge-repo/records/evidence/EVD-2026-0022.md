# R0059 DSpark 预算池实测输出：可调度 token 数与配对窗口收益

## 采集方法
上游轮次 R0059 在 910C 单机 16 个独立逻辑 die 的单实例上（`DP16 · TP1 · EP16`、DSv4-Flash W8A8、
util 0.88、block 32、prefix caching 关闭、`method=dspark` + `enforce_eager=true`），按 **A → C → B → D**
顺序换臂，每臂完整起服/清场一次，每次起服都做 16/16 rank ready 检查并抓取回显（含
`max_num_scheduled_tokens`）。每个工作点每臂跑 1–3 个「单元」（单元 = 一次完整并发批次），
同一工作点的 A 与 B 用**时间相邻的同窗口交错**（P1/P2 两轮）配对，跨时段数字只作参考。
逐请求 raw 全部落盘，收益用独立复算脚本（`verify_all.py`、`pair_analysis.py`）从 raw 池化重算。
精度侧另跑 6 seed × 3 重复的 temp=0 token 序列对照。

## 解释
证据支持：**DSpark 的 draft 长度与 `max_num_seqs` / `max_num_batched_tokens` 共用同一预算池**——实测
可调度 token 数随干预逐档上升（88 → 152 / 184 / 368），且长提示工作点的 TTFT 随分块数近线性下降
（B 预测 −42.1% vs 实测 −41.5%/−43.2%；D 预测 −75.9% vs 实测 −70.8%）。B 臂（K 7→5）在 32K×并发 8 的
两轮独立配对窗中吞吐 +59.56% / +60.57%（互差 1.0pp）、TTFT −41.5% / −41.9%、TPOT −2.92% / −2.23%，
且 KV 容量与基线相同；D 臂（batched 280→560）吞吐 +180.11%、TTFT −70.74%，代价 KV 容量 −13.0%。
两者均远超 2.37% 噪声底线。

证据**不支持**：短提示工作点（U1：吞吐仅 +5.09%、同窗口配对 ΔTPOT +11.9% 超 5% 门槛 ⇒ 不成立）；
EQ 类工作点（TPOT +9.24%~+11.05%）；精度侧任何结论（逐 token 一致率臂内与跨臂区间重叠 ⇒ 既不能证
等效也不能证退化）；≥128K 提示、其它 util、其它 block-size、其它部署形态；以及任何「步数/每步 token」
的独立归因（`/metrics` 为 16 rank 求和口径，无法与模型对齐）。摘录同时保留了两处**原件内部不一致**
（D 的 EQ 吞吐 30.08 vs 复算 18.77）与一处**未证实**段落，未做修饰。
