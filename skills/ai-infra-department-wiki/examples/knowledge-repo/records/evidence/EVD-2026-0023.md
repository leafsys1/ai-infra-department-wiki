# R0060 GDN exact-shape metadata cache 的逐 rank 计数与端到端噪声内输出

## Collection Method

上游轮次 R0060 在 aarch64 / Ascend 910B3 单机 `TP4 · DP1` 实例上（Qwen3.8-27B W8A8、
`max-model-len=36864`、`max-num-batched-tokens=8192`、`max-num-seqs=8`、util 0.80）对
`vllm_ascend/ops/gdn_attn_builder.py` 的 `_build_non_spec_chunked_prefill_metadata` 施加**追加式**
overlay 补丁（exact-shape metadata 缓存），以环境变量 `T0246_CACHE=0/1` 在同一实例上依次切臂，
每臂之间完整清理。机制侧逐 rank 埋点统计 builder 调用、miss/hit、`prepare_chunk` 与 H2D 次数，
并对命中复用对象做**逐元素验证**（11 个 metadata 字段比对，记录 `identical` 布尔）。端到端侧
`32K`（32760 token）提示 × 并发 `c1`/`c8`、输出 1024 token、每格每臂 3 个有效重复、每重复 8 条请求，
`nreq=8 / ok=8 / failed=0 / rejected=0`。收工后用恢复脚本还原 pristine 并核对文件哈希。

## Interpretation

证据支持：**exact-shape metadata cache 在真实 Qwen3.8-27B W8A8 路径上机制命中成立**——4 rank 合计
6012 hit / 60 miss（99.01%），miss 路径恒为 6 次 `prepare_chunk` + 6 次 H2D、hit 路径恒为 0/0，
命中复用对象在 188/188 条逐元素验证中对 11 个 metadata 字段全部一致、无误命中；且缓存关闭时语义
与基线一致（缓存开关不改变 builder 层调用模式）。

证据**不支持**：端到端性能收益——`32K/c1 +1.05%` 与 `32K/c8 −0.87%` 方向相反且均落在
`0.54%–1.56%` 的臂内噪声内，故判 UNVERIFIED，**不得把 −0.87% 写成收益**；逐 token exact 判据
（基线自身同 prompt 三次重复即出现 2–3 种 token 序列 ⇒ 无判别力，缺口显式保留）；其它 TP/DP 形态、
其它 `max-num-seqs`、≥64K 提示、其它量化口径或其它模型；以及源码级根因定位与多轮长跑下的缓存
淘汰收益（均未做）。
