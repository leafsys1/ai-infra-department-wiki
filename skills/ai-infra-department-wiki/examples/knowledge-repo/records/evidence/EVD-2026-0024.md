# R0057 单实例同 prompt 重复请求的 prefix cache 计数器增量（命中恒为 0）

## 采集方法
上游轮次 R0057 在 arm B（`--enable-prefix-caching`）的单实例上，对同一 API 实例（同一服务端口）
依次发送逐字节相同的 512-token prompt，并在每条请求**前后**读取同一 engine 的累计计数器
（`prefix_cache_queries`、`prefix_cache_hits`、`prompt_tokens_cached`），取 pre→post 增量作为该请求的
观测。共 5 条请求：P1 连发两次（R1/R2）、另加一条不同串（P2/R3）作对照、以及一组独立的 P3 连发两次
（R4/R5）作重复。每条请求都记录 prompt 的 SHA-256、prompt token 数、HTTP 状态。判据在执行前冻结。

## 相关输出
见 `locator` 指向的冻结摘录。含：逐请求表（5 行：prompt SHA-256、512 prompt tokens、HTTP 200、
`Δqueries=512`、`Δhits=0`、`Δprompt_tokens_cached=0`）；执行前冻结的四分支判据表（命中链存在 /
机制不可用硬否证 / 指标口径问题不算否证 / 请求失败作废）；边界 3 条（成立条件、未排除项与根因未定位）。

## 解释
证据支持：**在本口径内（同一 API 实例、同一端口、512-token 全整块 prompt、arm B 参数），
prefix caching 的命中链不可用**——查询数按整串长度增加（+512）说明前缀缓存查询路径确实被调用，
而命中数与缓存 token 数恒为 0；P3×2 的独立重复给出同样结果，未观察到偶发命中。这使「端到端收益」
在本口径内不可得，上游据此将该轮归档为 REVERT。

证据**不支持**：任何根因判断。上游原文写「根因未定位（UNVERIFIED）：为何 arm B 下同实例同串不命中
（DP 分组是否禁用本地 block 复用 / hash key 是否含 rank 维度），本轮无证据，**不得臆测**」——本记录
同样不做归因。也不支持其它 block-size、更长 prompt、其它 util 下的结论；并且本轮**无性能测量**，
不得把命中为 0 写成任何性能退化比例。
