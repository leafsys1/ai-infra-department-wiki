## 相关输出
摘录件（`locator`）逐字保留了：①主体 1 的判决——`vllm/config/vllm.py` 中显式端点是**追加**进候选集合
（不是替换），但先过守卫 `if compile_range_end is not None and x < compile_range_end and x > 1`
（2006–2014 行，同目录 README 写作 2010 行，两处行号**原样并存**），而
`compile_range_end = self.scheduler_config.max_num_batched_tokens`（1913–1914 行）；本部署候选值全部
**≥** 该值 ⇒ 守卫全部筛掉、显式项被静默丢弃、生效端点 100% 来自派生值；运行期只读佐证 5 次起服的
「入参 → 生效值」左值恒 `None`，右值为 `[560] / [1120] / [560] / [1120] / [280]`；②主体 2 的判决——
每次观测 = **一个引擎步**（one set of `EngineCoreOutputs`）内 `prompt_token_stats.computed +
num_generation_tokens`，prefill 项按请求**一次性**计入「该请求本地真实计算的 prompt token 总数」
（`num_computed_tokens = num_prompt_tokens - num_cached_tokens`），**不是本次 chunk**；③11 个单元的

请求级 `prefill_cnt Δ` 恒 1 的单元 11/11；④逐单元增量表节选（含 B 臂预热异常单元 `iterations=46`、
`bucket_le1_delta=20.0`）；⑤三个只读文件的 sha256 与行号；⑥原样保留的异常与三条缺口（沙箱缺口、

## 解释
证据支持两条**只读闭证**：①在本 vLLM / vllm-ascend 版本上（源码 sha256 已登记），把
`compile_ranges_endpoints` 显式设为 ≥ 调度预算的值会被守卫丢弃，生效值只来自 `max_num_batched_tokens`
⇒ 「用显式固定 compile 范围隔离纯调度收益」的干预设计在该版本上**不成立（设了等于没设）**；
②`vllm:iteration_tokens_total` 的观测粒度是**引擎步**、prefill 分量是「该请求的全部待算 prompt token」
而非「本次 chunk」，因此其直方图桶计数**不能**当作分块 prefill 步数——11/11 单元的机械复算与该语义
自洽（桶计数与 `iterations Δ` 不是同一粒度），计数可自行重算。

证据**不支持**：不支持「`batched` 560→1120 没有收益」或「被闭证对象 R0054 的数字无效」——本轮不触碰
R0054 的性能数字与 UNVERIFIED 状态，只撤回其中一处强因果措辞；不支持把主体 1 的守卫行为外推到其它
版本（换版本须重新核对行号与守卫）；不支持任何收益量级结论（两条都是成立/不成立的存在性判定）。
