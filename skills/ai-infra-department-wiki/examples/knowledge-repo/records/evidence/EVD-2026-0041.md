# 单一基础镜像交付形态的冻结摘录：交付物清单、每模型三文件、版本锁定与下载脚本

## 采集方法
素材是公开仓 `https://github.com/leafsys1/ascend-910b-model-adaptation`（HEAD `0da26df`）中的
交付物文档与实样文件：`README.md`、`customer-deliverables/README.md`、
`customer-deliverables/tools/download_model.sh`、
`customer-deliverables/models/Qwen3-1.7B/{run_config.env,model_metadata.yaml,bench_result.json}`、
`docs/REPOSITORY-AND-EVIDENCE-RULES.md`、`skills/ascend-model-router/SKILL.md`。

摘录方式：逐字摘出关键行，写入本仓 `artifacts/2026-09-23-single-base-image/excerpt.md`；
内部目录路径与端口号以 `…` 省略，其余文字未改写。摘录文件自身的 SHA-256 即 frontmatter 的 `source_sha256`。

## 相关输出
```
1 万个模型无法按「每个模型打一个镜像」交付（存储扛不住）。因此采用**「单一基础镜像 + 每模型最小文件」**：
- **镜像只有 1 个**（`quay.io/ascend/vllm-ascend:v0.23.0`，版本锁定）
- **每个模型交付 3 个小文件**（`run_config.env` + `model_metadata.yaml` + `bench_result.json`）
- **权重从不打包**，客户按文档从 hf-mirror 自行下载（关 XET）
客户要上一个新模型 = 填 2 个配置 + 下载权重 + `./run.sh` → 可复现的可用服务。

| NPU | Ascend **910B3**，64GB HBM/卡，aarch64 |
| 基础容器镜像 | **`quay.io/ascend/vllm-ascend:v0.23.0`** |
| 镜像内 torch / torch_npu | 2.10.0+cpu / **2.10.0.post4** |

- 正式 `bench_result.json` 一经创建不可变。
- 修正/补充：新增文件或对**非正式**汇总补字段，不重写历史。
1. 环境身份：镜像 tag、vLLM/vllm-ascend/CANN/torch_npu 版本
2. 权重身份：HF repo id + model.safetensors.index.json 分片清单
3. 验证结果：bench_result.json + 时戳
- ❌ 模型权重（>=GB 级，客户按文档自行下载）  - ❌ 容器镜像
```

## 解释
支持：交付物可以做到「镜像唯一 + 每模型仅少量文本文件」，权重与镜像都不进交付包，客户侧只需
填配置、下载权重、跑 `run.sh`；环境身份由锁定的镜像 tag 与版本表固定，因此每模型无需重复记录环境。
也支持「正式 `bench_result.json` 不可变」这条证据纪律：修正只能新增文件，不能重写历史。

不支持：不支持该形态已被独立第三方复现——本记录只读到了公开仓的文档与实样文件，未在本机复跑。
摘录中 `customer-deliverables/README.md` 正文写「每个模型 2 个文件」，而同文档目录树与
`docs/ACCEPTANCE-CRITERIA.md` 列出 3 个（含 `bench_result.json`）；两处口径差异保留原样，不作调和。
