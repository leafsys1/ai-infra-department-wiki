```
三个案例覆盖不同架构家族（Qwen2 / Phi3 / Qwen3），**走同一六步流水线、零代码改动**。

### Step 0：分类
`ascend-model-router` 判定 route / target skill / 等级。config-only 优先。
### Step 6：交付物
`run_config.env + model_metadata.yaml + bench_result.json` 三件套 + 复现演习。

- **A**：工具链已支持 + 权重可加载 → 全自动。主流文本 LLM 占绝大多数。
- **C**：当前工具链不支持（异构注意力头、架构不在支持表、model_type 版本过新）→ 人工。

- **复现演习必须真实跑**，不能只「相信能跑」。
- **可复现**：`reproduce_steps` 每步都必须是可直接执行的命令。
3. **False-ready 纪律**：`Application startup complete` + `/v1/models` 200 ≠ 成功，必须过真实请求门。
```

## 解释
支持：同一套六步流水线可以跨架构家族复用（Qwen2ForCausalLM / Phi3ForCausalLM / Qwen3ForCausalLM），
三个模型均标为 A 级、零代码改动，并各自给出稳态 TTFT/TPOT 与「完整三件套」交付物；也支持分类阶段
「先 config-only」与「吃不准归 C 级」的决策取向，以及「复现演习必须真实跑」的验收口径。

不支持：不支持把这些数字外推到其他架构或更大模型——公开仓另记录 `Mistral-7B-Instruct-v0.3`
（68.11ms / 17.83ms）、`internlm2_5-7b-chat`（55.79ms / 16.54ms）、`DeepSeek-R1-Distill-Qwen-7B`
（58.27ms / 70.4 tok/s）等，但本记录只摘录其中三模型的口径，且**未在本机复跑**。
摘录中 `docs/STATUS.md` 记「vLLM 0.23 实际支持 300+ 架构，原内置仅约 30 个」这一修复，
说明「架构支持表过时会把新主流架构误判 C 级」；该结论来自文档自述，本记录未独立验证。
