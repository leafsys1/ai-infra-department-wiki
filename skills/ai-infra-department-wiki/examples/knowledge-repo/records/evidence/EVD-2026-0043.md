# 同名镜像 tag 跨环境复现事件的冻结摘录：交付文档的摘要字段与容器 CANN 环境要求

## 采集方法
从本机交付工作区的内部归档里逐字摘出三处原文：视频生成类交付包的 `DEPLOY.md` 交付物表（含
「运行镜像」与「镜像摘要」两行）、跨环境复现记录里的公共基础镜像摘要行、以及容器运行要点里的
CANN 环境脚本要求。摘录只做删减与路径/命名空间脱敏，不改写文字、不改动数字。

## 命令
```bash
sha256sum <内部归档>/orig/delivery/wan2.1-t2v-1.3b/DEPLOY.md
sha256sum <内部归档>/orig/delivery/remaining7_round3_agentA_findings.md
```

## 相关输出
见本记录 `locator` 指向的冻结摘录，含：

- 交付物表里的 `镜像摘要` 行：自建交付镜像以 `@sha256:1745a7954d49…` 形式固定到交付文档；
- 公共基础镜像 `quay.io/ascend/vllm-ascend:v0.23.0` 的 digest
  `sha256:471744200c5d0c768c1f6c6a6816dcae0fd551de2487d4d129b6fb750024ce6a`；
- 容器运行要点：`--privileged`，并 source CANN 三件套（`ascend-toolkit` + `ascendnpu-ir` + `atb`）。

## 解释
证据支持两件事。第一，交付文档把**镜像摘要**当成交付字段来记——这只有在「tag 不能标识构建」的
前提下才有意义；同一 tag 在不同环境可以是不同构建。第二，镜像内部的 CANN 环境脚本是复现的必要
前提之一（缺 `ascendnpu-ir` 等 `set_env.sh` 会报 `0x7020010` 一类环境错误），所以「同名 tag 的旧构建」
完全可能表现成「交付包在 A 环境通过、在 B 环境失败」。

证据**不支持**具体摘要值的断言：两台环境上的摘要比对输出与旧构建摘要保存在内部交付归档，
未随本知识仓发布（受控指针）。因此本记录状态为 `observed`，而不是 `verified`。
