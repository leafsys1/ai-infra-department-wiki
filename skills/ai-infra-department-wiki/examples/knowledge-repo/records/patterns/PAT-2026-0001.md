# 容器内下载段的引号嵌套会截断整份交付脚本

## Trigger Signals

交付脚本在任何机器上都以 `syntax error near unexpected token` 失败；错误行指向 `docker run ... bash -lc '...'`。

## Root Cause

在 `bash -lc '...'` 的单引号体内再写 `\'` 试图转义单引号。bash 的单引号字符串内 `\'` 不构成转义，
第一个 `'` 直接结束字符串，后续内容成为裸文本，整份文件解析失败。

## Action Pattern

不要把变量插进引号体内。用 `-e` 把值传给容器，容器内用 `os.environ` 读取：

```bash
docker run --rm -e SS_REPO="${MODEL_REPO}" -v ./models:/w "${IMAGE}" \
  bash -lc 'python3 -c "import os; print(os.environ[\"SS_REPO\"])"'
```

外层保持单引号体，内层双引号属于容器内的 shell，两者不再互相嵌套转义。

## Preconditions

脚本由模板批量生成、且下载段在容器内执行。

## When Not To Apply

值中本身含单引号且必须保留时，应改用 `printf '%q'` 或临时文件传参，而不是继续加转义。

## Minimum Validation

对每个生成产物执行 `bash -n`；批量生成后必须全量执行，不能抽查。

## Counterexamples

仅当生成器不插入任何变量、或下载段在宿主机而非容器内执行时，该失败模式不出现——但这不构成
“可以不检查”的理由。
