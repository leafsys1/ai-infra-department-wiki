# 下载前探测：api/models 是存在性判据，resolve 不是

## Trigger Signals

批量下载前置检查把大量实际可用的仓库标记为不可用，或反之把不存在的仓库放进了下载队列。

## Root Cause

用 `resolve/main/config.json` 的状态码判定仓库是否存在。该路径只代表“这个文件在这个位置”，
仓库存在但文件不在该路径时同样返回 404。

## Action Pattern

```bash
curl -sL -o /dev/null -w '%{http_code}' https://<mirror>/api/models/<org>/<repo>
# 200 = 存在；401 = 不存在
```

把存在性判定与可下载性判定分开：存在性用 `api/models`，可下载性由实际下载首个小文件确认。

## Preconditions

镜像站提供 `api/models/<repo>` 接口；探测需要网络可达。

## When Not To Apply

需要判断“某个具体文件是否存在”时，`resolve` 路径的 404 才是正确语义——此时不要改用 `api/models`。

## Minimum Validation

对已知存在、已知不存在、已知存在但缺该文件三类样本各取一例，核对状态码是否符合预期。

## Supporting Cases

CASE-2026-0002。

## Counterexamples

部分仓库会把 `resolve` 请求重定向到新命名空间，跟随重定向后可能返回 200——这说明状态码语义
随仓库策略变化，判据必须按批次重新标定。
