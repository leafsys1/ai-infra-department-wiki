# 同名镜像 tag 不等于同一构建：跨环境前必须比对 digest

## 触发信号
同一份交付包在 A 环境复现成功、在 B 环境失败，而两边的 `run.sh` 与镜像 tag 完全相同。

## 根因
本地同名 tag 曾用错误的基础镜像构建过；tag 是可覆盖的标签，不是内容标识。两边的 tag 相同，
镜像摘要不同，容器内的驱动适配层与运行环境因此不同。

## 处理模式
跨环境复现前先比对镜像摘要：

```bash
docker image inspect <image> --format '{{.Id}}'
```

摘要不一致时，不要依赖仓库同名 tag 重新拉取，改为 `docker save` / `docker load` 传递确切构建，
并在交付文档中记录该摘要。

## 前置条件
交付依赖自建镜像，且镜像在两个及以上环境间传递。

## 不适用场景
交付完全使用公共镜像且 tag 由上游维护时，摘要差异属于上游更新，应按版本号而非摘要比较。

## 最小验证
在目标环境实际启动容器并执行一次最小前向，确认适配层加载成功，而不是只看 `docker images` 列表。

## 支持案例
`CASE-2026-0043`（同名 tag 在两台环境上是不同构建，交付包一台通过、一台失败）。

## 反例
仅当镜像在两边都由同一构建流水线产出、且 tag 含不可变版本号时，可以只比 tag。
