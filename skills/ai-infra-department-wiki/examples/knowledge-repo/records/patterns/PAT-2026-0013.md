# 倍数读数必须先扣除仪器地板

## Trigger Signals

同一个优化在不同计时口径下给出差一倍的倍数（kernel-only、摊销事件、朴素单 call）。

讨论里只给一个倍数，不说口径。

## Root Cause

每种仪器自带地板：harness 开销加 host 下发。小工作量时地板在总耗时里占大头，倍数被压低或抬高；不同口径的地板不同，因此不同轮次的倍数不可比。

## Action Pattern

1. 读数前先量仪器的地板（空窗口或空 event 窗口耗时）。
2. 报告倍数时写明口径，必要时同时给多个口径。
3. 若某口径下收益会被地板吃掉，明确写出「只采信该口径则应记 CONTINUE」这类结论边界。

实例（R0017，同一个优化）：

- kernel-only 口径 2.842×。
- 摊销事件口径 2.385× / 2.509×。
- 朴素单 call 口径 1.532×；该仪器含约 58.7 µs harness 地板加 34–54 µs host 下发（53.51 / 38.87 / 35.4 µs）。
- 源里明说：只采信朴素单 call 这一种口径，则本轮应记 CONTINUE，而不是 KEEP。

## Preconditions

能构造空工作量的对照测量（空窗口、空 event 窗口）。

能固定 host 下发次数，例如把下发摊销到批内多次 call。

## When Not To Apply

工作量远大于地板时（毫秒级以上算子）地板可忽略，但仍要写明口径。

倍数用于「占比 × 可见度」的上界计算时，地板已被占比吸收，不必重复扣除。

## Minimum Validation

空窗口基线加至少两种口径交叉。

两个口径的结论方向不一致时，取保守口径并写明。

## Supporting Cases

- R0017：三种口径 2.842× / 2.385×·2.509× / 1.532×，地板 58.7 µs 加 34–54 µs host 下发。

## Counterexamples

只报一个口径会让同批轮次之间不可比：R0015 的 85–93% 与 R0018 的 1.169× 都是局部口径读数，必须再乘占比与可见度才能用于立项（PAT-2026-0010）。

反面风险是把地板当收益：R0026 的单层改善 12.8–15.3% 在完整服务里只剩 0.49%，且两臂高度重叠。
