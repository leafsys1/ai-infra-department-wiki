# 同样卡数下「单实例大 TP」与「多副本小 TP」是两种产品形态，先定指标再选拓扑

## Trigger Signals

卡数固定，要选「一个 TP4 实例」还是「4 个 TP1 副本」。

讨论里只报一项指标：要么只报聚合吞吐，要么只报单流延迟。

## Root Cause

大 TP 把权重读拆到更多卡、降低单流 TPOT，但每步引入卡间通信；多副本提高聚合吞吐与首 token 速度，但单流 TPOT 差。两者服务的是不同目标，指标没先定就无法比较。

## Action Pattern

1. 先定指标：单流 TPOT、聚合吞吐、首 token 延迟，哪个是目标。
2. 再选拓扑，并同时报告三项，避免只报一项。
3. 换拓扑时把接受率、KV 容量这类联动量一起记下来。

实例：

- R0048：同样 4 张卡，TP4 聚合吞吐 +9.5%、单流 TPOT −35%；4×TP1 副本首 token 快 2.17×（201 ms 对 436 ms）。
- R0047：TP1→TP2→TP4 步时 ×1.352（TP2）/ ×1.887（TP4），未达事前预测 1.4–1.9×，每步约 4 ms 落在卡间通信。
- R0040：只换拓扑 DP1×TP8、推理语义与负载都不动：DSpark 接受率 44.34%→40.47%、TPOT −3.51%、Output TPS −2.16%，全指标回退。

## Preconditions

卡数固定且可自由选实例数。

权重完整性已验证：R0042 核验 25 个源文件 SHA256 与上游逐一相同，单卡起服成功。

## When Not To Apply

单请求低延迟且卡数不足时不必比。

吞吐目标已由并发满足时（PAT-2026-0015）也不该再为大 TP 付通信代价。

## Minimum Validation

同会话交错配对，同时记录首 token、单流 TPOT、聚合吞吐三项。

只报一项会误判。

## Supporting Cases

- R0048：聚合吞吐 +9.5%、单流 TPOT −35%、副本首 token 2.17×。
- R0047：步时 ×1.352 / ×1.887，约 4 ms/步通信。
- R0040：接受率 44.34%→40.47%，全指标回退。

## Counterexamples

R0040 说明换拓扑会同时动接受率与吞吐：只看 TPOT 会漏掉 Output TPS −2.16% 的回退。

R0047 的步时放大说明「拆更多卡一定更快」也不成立。
