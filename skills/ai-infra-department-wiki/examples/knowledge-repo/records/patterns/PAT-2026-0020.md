# 交付物必须客户自理：依赖我方环境的交付物在验收时判 FAIL

## 触发信号
- 交付包在交付方本机跑得通，客户侧「一键复现」失败。
- 失败报错是**环境类**而不是模型/算子类：容器内 NPU 初始化失败、`ModuleNotFoundError`、
  路径不存在、脚本整体语法错误、`argument --model: expected one argument`。
- 交付脚本里出现我方自建的镜像名，或指向我方本地/共享存储的权重路径。
- 客户必须先问「你那个镜像在哪」「权重放哪儿」才能跑起来。
- 验收时脚本实际使用的镜像 tag 与交付文档声明的不一致。

## 根因
交付物把**交付方的环境当成了默认前提**：本机已有自建镜像、已有权重池、CANN 环境变量已就绪、
卡未被其它容器占用、私有脚本就在手边。这些前提在交付方内部完全不可见——因为都成立，所以没人会发现
它们被写进了交付物。换到陌生环境后前提全部不成立，交付物同时暴露多处缺口。

根因不在模型与算子，而在交付物缺少「环境自理层」：该由交付脚本自己完成的解析、下载、补装、条件化，
被隐式推给了客户或我方运维。

## 处理模式
1. **镜像自理**：自建镜像引用一律替换为公共镜像；本地缺该镜像时自动 `docker pull`，拉取失败即退出并
   提示网络/仓库；替换前后镜像名必须打印出来（可审计）。
2. **权重自理**：默认权重路径必须指向**宿主机**真实目录；目录缺失或为空时回落到交付包内目录并自动下载
   （见 PAT-2026-0021）。
3. **依赖自理**：容器内缺失的 python 依赖自动补装（优先国内 PyPI 镜像，失败回退官方源）。
4. **环境自理**：容器内 source CANN 三件套（缺文件不阻断）；主机专有的 CANN 路径挂载条件化。
5. **权限自理**：把运行所需权限（如 `--privileged`）写进交付文档并由客户确认，不靠口头说明。
6. **脚本自律**：消除空参数传值；禁止单引号内嵌 `python -c`；生成后跑全量 `bash -n` 门禁。
7. **验收自理**：在清洁环境（新建容器、无自建镜像、无本地权重池、无我方 Skill）只按交付文档操作复现，
   以 `run.sh` 退出码与验收脚本的 errors/warnings 计数判定。

## 前置条件
- 交付形态是「容器 + 单入口脚本（`run.sh`）」，客户自己起容器。
- 客户环境能访问至少一个公共镜像仓库与一个权重源。
- 客户有一个可写的权重目录，且该目录不是交付方维护的共享存储。

## 不适用场景
- 客户明确指定镜像与内网权重源：此时「不依赖我方镜像」退化为「依赖客户镜像」，判据变成「镜像由客户
  指定且 tag 可核验」。
- 强隔离/涉密环境：交付物随客户介质进入，自理层按客户介质形态重写。
- 交付物本身就是镜像或算子库（不是可执行交付包）时，自理层落在镜像构建侧而非 `run.sh`。

## 最小验证
新建容器 → 只按 `DEPLOY.md` 操作 → 记录 `run.sh` 退出码 → 跑验收脚本记录 errors/warnings 计数 →
核对脚本实际使用的镜像 tag 与文档一致。**任一步要求我方资源，即判 FAIL。**
只在本机跑一遍不构成验证：本机所有前提都成立，缺陷一个都不会暴露。

## 支持案例
- CASE-2026-0040：54 个交付包在陌生环境复现时，失败全部集中在四类自理缺口（设备权限与 CANN 环境、
  自建镜像引用、内部权重路径、容器内缺失依赖），另有一处空参数脚本缺陷使一键复现 7/7 全 FAIL；
  补齐后清洁环境退出码为 0、验收脚本 0 errors / 0 warnings。
- CASE-2026-0041：单一基础镜像 + 每模型最小文件的交付形态，把环境身份固定在锁定的镜像 tag 上，
  权重与镜像都不进交付包，客户侧动作收敛为「填 2 个配置 + 下载权重 + `./run.sh`」。

## 反例
以下做法看着省事，但会在客户环境挂掉：

- **让客户用我方自建镜像**：省掉替换工作，但客户环境拉不到该镜像；原交付包正是依赖自建容器，
  在客户环境不可用，才改为公共镜像 + 自理层。
- **权重默认路径写成容器内路径或我方共享目录**：本机跑得通（因为挂载源恰好存在），客户机器上挂载源无效。
- **用常驻容器做验证**：省去每次起容器的开销，同时掩盖了两件事——新容器里 NPU 初始化需要 `--privileged`、
  新容器里 CANN 环境变量需要重新 source。这两类缺陷只在新建容器时才暴露。
- **把依赖写在聊天/口头说明里**：文档没写，客户机器上必然 `ModuleNotFoundError`。
- **交付脚本引用我方私有 Skill 或私有脚本路径**：客户没有这些文件。
- **只交付「能在本机跑」的脚本**：本机前提全部成立，等于没验证。
