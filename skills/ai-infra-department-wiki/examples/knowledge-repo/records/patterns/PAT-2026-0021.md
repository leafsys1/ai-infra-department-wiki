# 权重获取要有双通道与存在性判据：hf-mirror 直连 + 备用源，元信息走 api/models

## Trigger Signals

- 权重下载在客户侧失败，或大分片下载报 401。
- 交付脚本/文档只给了一条下载路径，失败后没有可执行的下一步。
- 文档只写「下载权重」，没有可直接复制执行的命令。
- 用 `resolve/...` 路径去判断仓库是否存在或能否下载。
- 只判断「权重目录存在」就认为权重就绪，不判断目录是否为空。

## Root Cause

三件事被混在一起：

1. **直连不可达**：huggingface.co 在国内通常直连不通，必须走镜像源。
2. **协议不兼容**：`huggingface_hub>=1.x` 默认走 Xet/CAS 协议，hf-mirror 不代理 Xet，大分片会 401，
   必须关掉 XET 回落到传统 LFS。
3. **判据用错接口**：仓库的**元信息**（如 `pipeline_tag`）与**文件内容**不是同一个接口；
   存在性/元信息应查 `api/models/<repo>`，`resolve/<rev>/<file>` 只用来取具体文件。

单通道 + 无判据的结果是：下载失败时交付方既不知道为什么失败，也给不出客户能执行的替代命令。

## Action Pattern

1. **通道一（优先）**：hf-mirror 直连，导出 `HF_ENDPOINT=https://hf-mirror.com` 与
   `HF_HUB_DISABLE_XET=1`。
2. **通道二（兜底）**：备用源（ModelScope 国内 CDN），通道一失败时自动切换；下载脚本自动检测 CLI
   （`hf` 优先，`huggingface-cli` 回退）。
3. **判据**：存在性与元信息查 `https://hf-mirror.com/api/models/<repo>`；取 `config.json` 等具体文件
   才用 `resolve/main/<file>`。分类/判型优先 config-only，不为判型下载完整权重。
4. **本地就绪判据**：权重目录不存在**或为空**即视为缺权重并触发下载。
5. **回落路径要可执行**：脚本在所有通道都失败时，打印客户可直接复制执行的命令，而不是只报错退出。
6. **权重身份**：下载完成后核对分片清单（`model.safetensors.index.json`）完整，作为权重身份留痕。
7. **文档化**：交付文档给出可复制的下载命令，不写「请自行下载权重」。

## Preconditions

- 客户网络可达至少一个镜像源；目标目录可写且磁盘空间足够。
- 已知权重仓库 ID 与期望的分片清单。

## When Not To Apply

- 内网离线环境：改用客户预置权重，通道二换成客户内网制品库地址。
- 权重随镜像内置（小模型）：此时判据落在镜像 tag 与镜像内文件校验，而非下载。
- 企业级制品库已代理 HF 且协议兼容：通道一即够，但仍应保留失败时的可执行提示。

## Minimum Validation

在无权重的新目录/新容器里跑一次下载；核对下载后的分片数量与 `model.safetensors.index.json` 一致；
人为断开通道一（或指向不可达 endpoint）验证通道二确实被触发。仅「本机已有权重」不构成验证。

## Supporting Cases

- CASE-2026-0040：交付脚本在权重目录缺失/为空时先回落到交付包内目录，再按「hf-mirror 优先、
  ModelScope 兜底」自动下载；hf-mirror 大文件走 XET 失败时切备用源，全部失败则打印多条可执行的回落路径。
- CASE-2026-0041：单一基础镜像交付形态里权重从不打包，交付文档给出可复制的下载命令
  （`HF_ENDPOINT` + `HF_HUB_DISABLE_XET=1` + `download_model.sh`），下载脚本自动在 `hf` 与
  `huggingface-cli` 之间回退。

## Counterexamples

- **只准备 hf-mirror 一条通道**：一旦大分片走 Xet 被拒（401），客户侧没有任何可执行的替代动作。
- **不关 XET**：`huggingface_hub>=1.x` 默认走 Xet/CAS，在镜像源上直接失败。
- **用 `resolve/...` 路径判断仓库是否存在**：该路径只用于取文件内容，判存在性/元信息应查 `api/models/<repo>`。
- **只判「目录存在」不判「目录非空」**：中断的下载会留下空目录，脚本误判为已就绪，随后加载失败。
- **文档只写「下载权重」**：客户拿不到可执行命令，等于把下载成本转移给客户。
- **为判型先下载完整权重**：判型只需 config 与元信息，下载 20GB+ 权重再分类是纯浪费。

## Skill Evolution Status

尚未提升为 skill。候选方向是把「双通道下载 + 存在性判据 + 分片核对」合并进交付自查脚本的只读检查段；
当前无 held-out 验证，暂不提升。
