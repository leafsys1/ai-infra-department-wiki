# 跨环境交付复现的标准流程

## 前置条件
- 已有可交付的模型包（含 `run.sh`、说明与交付清单）。
- 目标环境可访问容器仓库与权重下载通路。
- 已确认目标环境的设备可用性与空闲情况。

## Read-Only Checks

```bash
docker image inspect <image> --format '{{.Id}}'   # 与交付记录比对摘要
npu-smi info                                      # 设备型号与空闲状态
df -h <workspace>                                 # 权重落盘空间
```

## 执行步骤
1. 传输交付包（不含权重）到目标环境。
2. 核对镜像摘要；不一致时用 `docker save` / `docker load` 传递确切构建。
3. 在目标环境下载权重，落盘到挂载点，而不是容器可写层。
4. 执行 `SMOKE=1 ./run.sh`，记录退出码与语义成功判据（不只是 rc=0）。
5. 执行完整 `./run.sh`，保留原始日志与逐请求数据。
6. 逐包登记：成功/失败、失败原因、所需人工干预。

## 成功标准
- 退出码为 0，且语义成功判据成立（输出可解码/结果非空）。
- 全流程只使用交付包自带说明与公开通路，无交付方在场。

## 失败处理
- 镜像摘要不一致 → 停止，先对齐构建。
- 权重下载失败 → 记录状态码与 URL，区分“不存在”与“网络不可达”。
- 设备初始化失败 → 检查权限与驱动适配层是否随镜像带入。

## 回滚
删除目标环境新建的容器与权重目录即可；本流程不修改目标环境已有服务与数据。

## 权限与安全边界
只读检查之外的动作（下载大资产、占用设备）需先确认授权与资源；无授权时记录阻塞并继续其余步骤，
不得把未执行写成通过。
