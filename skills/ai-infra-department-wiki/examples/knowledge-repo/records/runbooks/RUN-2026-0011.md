# 零卡静态否证流程：占加速器之前先否掉一个方向

## Preconditions

有可读源码或容器内文件系统，或可回显的 CLI 与配置字段。

只允许只读操作：grep、读 help、读配置回显、读既有 /metrics 快照。不允许起停服务、改配置、占卡。

判决口径在取证前写定，例如「本方向存在性的判据是五路证据全部 0 命中」。

## Read-Only Checks

证据清单五路，逐路记「命令 → 落盘文件 → 命中数」：

1. CLI 全量 help：`vllm serve --help=all`，落盘后按同族模式 grep。
2. 配置字段全表：目标 Config 的字段回显逐行核对。
3. 直接传参：用引擎自带 argparse 探针传该 flag，看退出码。
4. 容器内全域 grep：在容器内对整个安装树 grep 关键词。
5. 目标目录关键词：在机制应该存在的目录（如 `vllm/v1/core/`）grep 同族关键词。

辅助只读证据：既有 /metrics 快照（桶表增量）、既有运行日志与配置回显。

预期输出（示例 R0056）：第 1 路 1826 行 0 命中、落盘文件 0 字节；第 2 路配置字段全表不含该字段；第 3 路 `error: unrecognized arguments`、rc=2；第 4 路容器全域 grep 0 命中；第 5 路目标目录三关键词 0 命中。

## Procedure

**Step 1 写判决口径**：明确本方向「存在性」的判据是什么。产出：一句可核对的话（例如五路 0 命中）。

**Step 2 逐路取证**：每路落盘，记文件名与字节数、命中行数。产出：五路证据文件加命中数。

**Step 3 判存在性**：全部 0 命中 ⇒ 机制在本版本没有同名入口，判否证，按 REVERT 归档并写「本轮无性能测量」及原因。

**Step 4 判是否生效**（机制存在时）：用只读观测看计数是否真的动。R0057 的实例：逐字节相同的 512-token prompt 重复请求 Δqueries=+512 而 Δhits=0、Δprompt_tokens_cached=0，独立重复同样 Δqueries=512、Δhits=0 ⇒ 查询路径进入但命中链不可用。

**Step 5 判冻结配置是否允许**（机制存在且生效时）：R0037 的实例：上游 draft ACL graph 机制与本地 host/launch 根因匹配，但冻结配置明确 `enforce_eager=true`，关闭它会改变冻结执行配置 ⇒ 按 NOT_APPLICABLE 归档。

**Step 6 写缺口**：把「哪一步无法本地取证」原样写出来（本地没有该源码、判决点只能在容器内取证），不要凭印象补结论。产出：缺口清单，交给后续轮次闭合。

## Success Criteria

存在性否证：全部取证路 0 命中，每路有落盘证据与命中数。

不生效判据：查询路径进入但计数不动，且独立重复可复现。

不适用判据：机制与根因匹配，但冻结配置不允许，且改变配置会破坏可比性。

三种情形都要写「本轮无性能测量」并说明缺哪一步才能测。

## Failure Handling

任一路命中 ⇒ 不能判否证，转占卡实测（RUN-2026-0010）。

判决点无法本地取得（本地无源码、只读受限）⇒ 记为缺口并交由容器内只读取证闭合，不得用「印象」或「上游应该有」代替。

只读证据只能支持严格表述：例如「本证据不支持该缺口已被触发」（R0056 主体 B 为 n=1 串行负载、未覆盖满载、桶边界无法分辨 8-token 窄带），不能写成「缺口不存在」。

## Rollback

本流程只读，不改配置、不起停服务，无回退动作。

取证过程若落了临时文件，取证结束后清理，只保留结论与命中数记录。

## Permission And Safety Boundary

全程零卡、零服务操作。

任何需要起服或占卡的验证另立轮次并先取得授权。

不得为取证改动冻结配置：R0037 的结论正是「关闭它会改变冻结执行配置，因此不实现」。
