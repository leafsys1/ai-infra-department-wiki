# 客户自理交付包的打包与验收流程

## 前置条件
- 交付包在**交付方本机**已跑通，且有 `DEPLOY.md` + `TEST_REPORT.md` 说明与测试记录。
- 基础镜像已锁定 tag，且该 tag 从客户可达的仓库能拉到（公共镜像优先；自建镜像视为不可用）。
- 客户侧具备：容器运行时 + NPU 驱动 + 可访问的权重源；已知该型号的卡型与设备权限要求
  （是否需要 `--privileged`）。
- 已记录每个被改写文件的**原文件 SHA-256**（改前身份），否则回滚与审计无从下手。

## Read-Only Checks

以下检查只读、不改变系统状态，先做：

```bash
docker image inspect <基础镜像tag>            # 本地是否已有；缺失则判为需要 pull
npu-smi info                                  # 卡是否空闲、是否已被其它容器占用
bash -n <交付包>/run.sh                       # 语法门禁（全量，不抽查）
sha256sum <交付包>/run.sh                     # 与改前清单比对
```

判读：卡被其它容器占用时，容器内会出现与权限缺失**相同**的初始化失败报错，必须先排除占用再看权限。

## 执行步骤
**1. 定交付目录结构**

- 普通型：`run.sh` + 每模型配置 + `DEPLOY.md` + `TEST_REPORT.md`。
- 代码内嵌镜像型：额外带 `Dockerfile` + 构建上下文（buildctx）。
- 两种情况都**不打包**模型权重与容器镜像：权重只留可复制的下载命令，镜像只留 tag。

**2. 生成 run.sh（模板 + 每模型值）**

- 禁止 `bash -lc '…python -c "…"'` 这种单引号内嵌写法：引号嵌套一旦失衡，整份脚本会以语法错误
  结束，且报错位置与真实原因无关。
- 需要向容器内传值时必须用 `-e VAR="值"` 传入、在 python 侧用 `os.environ["VAR"]` 读取。
- 消除空参数：`--flag $VAR` 在 `VAR` 为空时会让命令行退化成「有选项无值」，必须显式处理。
- CANN 环境：容器内依次 source `ascend-toolkit`、`ascendnpu-ir`、`nnal/atb` 的 `set_env.sh`，
  文件不存在时不阻断（主机专有路径要条件化）。
- 宿主专有的 CANN 路径挂载同样要条件化：路径存在才挂。

**3. 装环境自理层**

- 镜像自理：识别自建镜像引用并替换为公共镜像（打印替换前后镜像名）；本地无镜像时自动 `docker pull`，
  拉取失败即退出并提示网络/仓库。
- 权重自理：默认权重路径指向宿主机真实目录；目录缺失或为空时回落到交付包内目录并自动下载（见 PAT-2026-0021）。
- 依赖自理：容器内缺失的 python 依赖自动补装（优先国内 PyPI 镜像，失败回退官方源）。

**4. 设备权限**

新容器统一带 `--privileged --security-opt label=disable --network host` + 常规设备挂载
（davinci / manager / devmm_svm / hisi_hdc）。

**5. 权重下载双通道**

hf-mirror 直连（关闭 XET）优先；大文件走 XET 失败时回退备用源；下载完成后核对分片清单完整。

**6. 打包自查**

全量 `bash -n` 通过 → 跑一次 smoke → 核对镜像 tag 与所需权限是否写进文档。

**7. 验收三步（必须在清洁环境）**

1. **冒烟**：新建容器跑 smoke，记录退出码与产物校验。
2. **全量**：同一容器或再新建容器跑 full，记录退出码、关键时延与产物校验。
3. **权限与镜像 tag 核对**：容器参数与文档一致；脚本实际使用的镜像 tag 与文档声明一致。

**8. 交付文档**

`DEPLOY.md` 写清「客户必须改的 2 个配置」（端口、宿主机权重路径）+ 权重下载命令 + 复现步骤；
`TEST_REPORT.md` 记录退出码、产物校验与验收脚本输出。

## 成功标准
- 陌生环境（新建容器、无自建镜像、无本地权重池、无交付方 Skill）下 `run.sh` 退出码为 0。
- smoke 与 full 两轮均通过，产物可校验；验收脚本 0 errors、0 warnings。
- 全量 `bash -n` 无语法错误；脚本实际使用的镜像 tag 与文档一致。
- 设备权限要求（如 `--privileged`）与权重下载命令都写进了交付文档，不靠口头说明。

## 失败处理
| 现象 | 首查 | 处置 |
|---|---|---|
| 容器内 NPU 初始化失败 `aclInit 507899` / `Resource_Busy` | 是否 `--privileged`；卡是否被其它容器占用 | 补 `--privileged`；停掉占用容器的进程后重试 |
| 报 `0x7020010` | CANN 环境变量 | 容器内 source CANN 三件套 |
| `ModuleNotFoundError` | 镜像内是否含该依赖 | 走依赖自理层在容器内补装 |
| `argument --model: expected one argument` | `run.sh` 是否有空参数 | 消除空参数传值 |
| 镜像拉取失败 | 网络/仓库可达性 | 退出并提示；不改用自建镜像 |
| 权重下载失败 | hf-mirror 是否重定向到 XET | 关闭 XET；仍失败切备用源 |
| 脚本整体语法错误 | 引号嵌套 | 改用 `-e` 传值 + `os.environ`，重跑全量 `bash -n` |

## 回滚
- 按改前 SHA-256 清单逐文件还原 `run.sh`（清单在批量改写时已逐条记录）。
- 不改动客户既有目录结构，不删除客户已下载的权重。
- 若镜像被自动替换，回滚时以脚本打印的替换记录为准，恢复客户指定的镜像 tag。

## 权限与安全边界
- `--privileged` 放宽容器安全边界，必须在交付文档中显式写明并由客户确认；不能靠脚本静默加。
- 自动替换镜像、自动拉镜像、自动下载权重都会改变客户环境，脚本必须打印每一步动作，保留可审计痕迹。
- 下载与补装走客户网络，需客户事先同意；交付脚本内不得写任何凭据。
- 本文档中的卡占用排查涉及停止他人容器，须先取得对应使用者同意。
