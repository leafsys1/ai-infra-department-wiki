# 数据真实性：证据强度与威胁边界

本 skill 不能仅凭文件证明数据不是伪造的。一个人能同时编造 CSV、日志、时间戳和哈希。SHA-256 只能证明两个字节串是否一致；没有预先可信摘要，不能证明文件是某次实验产生的。

## 必须分别报告的维度

| 维度 | 检查 | 可以支持 | 不能支持 |
|---|---|---|---|
| 文件完整性 | 白名单、大小、哈希、冻结包 | 本轮读取的内容和交付包可核对 | 原始来源诚实 |
| 数据自洽 | 计数、字段、单位、ID、时序、统计重算 | 已配置检查没有发现内部矛盾 | 测量是真实执行或无遗漏 |
| 来源核对 | 独立渠道读源系统日志、任务ID、镜像/权重/进程身份 | 指定窗口有相符源记录 | 源系统本身没被篡改 |
| 独立复测 | 独立操作者与受控采集，重现基线和主要结论 | 结论在重测条件下可重现 | 原作者历史每条数据真实 |
| 人员/权限独立性 | 审核者身份和数据控制权限分离 | 审核不是作者自签 | 绝对无利益冲突 |

每项写“已核/未核/异常”，包含证据ID、核查者、时间、工具、权限限制。脚本的 authenticity=NOT_ESTABLISHED 是有意保守；智能体另写人工可读 provenance.md，不能编辑脚本结果来伪装认证。

## 源头交叉核验

1. 从预先登记的实验计划/调度系统取完整 run 清单，再与提交的 run 清单核对。仅有 CSV 不能证明失败轮没有被省略。
2. 以 run ID、request ID、输入/输出长度、起止时间关联客户端与服务端；时间戳须声明时区和时钟偏差。
3. 查 FINISH/FAIL/取消/超时语义，不信包装器退出码。哨兵值的含义从实际工具源码或协议读取，不把 99999 无条件认作造假。
4. 对“刚跑完”的报告核对源文件时间、进程运行身份与日志，但文件 mtime 可改，只是辅助线索。
5. 对哈希的预期值注明谁何时通过什么受控渠道发布。同一份可编辑 manifest 自填的哈希无独立性。
6. 对聚合表回溯原始请求；转换保留代码、版本、字段映射、原始条数、剔除/失败原因。不能只保留成功样本。
7. 源系统无访问权限时仍完成本轮：报告材料自洽性、不可核查内容和最小补证请求。

## 报告用语

可用：“提供者提交的 CSV 内部自洽；未取得服务端源日志，实验发生性尚未独立核验。”
可用：“在授权源系统读取到同 run ID 的记录；独立复测在列明条件下重现了主结论。不能据此追认全部历史数据。”
禁用：“没有异常，因此数据真实”“哈希一致，真实性100%”“智能体评审通过，保证客户无风险”。

疑点记录为疑点，不能凭重复数字或不常见分布指控造假。取不到证据写缺证据，不擅自填实验结果。

## 私密性

原始客户数据/提示词不需要进入报告；可使用获准的去标识摘要。证据文件可能包含令牌、地址、账号；显式白名单不等于自动脱敏。内部包须受控存储；对外包由批准的文件列表构建，不直接上传整个工作目录。脚本不联网，不读取环境凭据，不验证签名或提供防篡改存储；需要更强证明时使用组织自有受控日志/签名归档/审批系统。
