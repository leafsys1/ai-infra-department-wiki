# 九道技术门禁

所有项目先冻结验收依据。PASS=本轮智能体提出的、有具体证据的技术判断；不等于第三方认证。FAIL=已证实不满足；UNVERIFIED=证据不足；BLOCKED=权限/资源/工具阻塞；NA=与已冻结范围无关且理由得到审阅。执行受阻不等于技术失败。

| 门禁 | 必做检查 | 不足时如何处理 |
|---|---|---|
| G0 范围与指标 | 逐条 claim 与客户验收映射；单位、时间窗口、样本数、主指标/护栏、容差来源、计划冻结版本 | 缺阈值不自定承诺；标 UNVERIFIED |
| G1 环境与运行身份 | 硬件/拓扑、权重身份与量化、tokenizer、镜像摘要、引擎/驱动/库、补丁、实际加载路径、最终配置 | 源码存在或镜像标签不能独立证明正在运行版本 |
| G2 正确性与质量 | 可信参考实现、误差容差来源、shape/dtype/batch/边界/并行/缓存/图回退；真实模型质量和业务功能 | 禁放宽标准、删除失败样本；正确性失败阻断收益结论 |
| G3 机制与命中 | intervention→mechanism→observable；路径命中、计数/trace、fallback；profiling 的测量扰动 | 纯部署无机制 claim 可 NA；改动未命中不能归因给补丁 |
| G4 性能与可比性 | intended difference；其余变量控制/解释；原始逐请求/逐轮数据；公平基线；失败与超时；warmup；噪声；重算全部客户数字 | 只比最好轮、跨模型混比、只报成功吞吐均不得直接放行 |
| G5 稳定性与恢复 | 有依据的时长/负载；错误率、worker/rank、内存趋势、队列/缓存、恢复及回退；测试后环境状态 | 默认不做破坏性故障注入；无权限记未测而非 PASS |
| G6 独立复现 | 按冻结手册在等价环境复现；记录操作者、权限、命令/回显/如何读；隐含步骤及偏差 | 同一作者换 agent 只算第二上下文复核 |
| G7 交付一致性 | 文档/命令/配置/结果/补丁版本逐项映射；实际打开交付文件；脱敏；模型/软件许可及分发授权 | 文件可打开不代表正确；补丁许可证、权重权利不明不代签 |
| G8 冻结与归档 | 全部 claim 处置、证据/报告索引、manifest 与哈希；遗留项责任人；受控外部批准记录（若已有） | 无独立批准为待放行，不可由 agent 自填名字批准 |

## 分级与成本

L1 探索：材料和局部证据核对，不对客。L2 技术结论：额外正确性、机制、性能和独立复核。L3 客户交付：额外端到端复现、稳定/恢复和授权放行。风险决定测试深度；已可信且适用的历史证据可引用，但须核对版本和条件。对客承诺、计算语义/量化变化、缓存生命周期、跨节点传输均须提高审查深度。

变更算法应查准确率/误差；只调部署参数也须验证模型身份、输出完整性及接口语义。并发、随机性可能造成输出差异，应使用事先约定的质量标准。不要强制所有项目比较逐 token 完全一致。

## 性能的人工/智能体评估

脚本仅给描述统计，不能替代实验设计。A/B 按实际批次配对；环境漂移必须显式说明。一次改变多个参数可支持“整套配置”的结果，不能归因给其中一个算子。超时和错误请求必须进入失败率分母。吞吐须明确总窗口、输入/输出 token 和成功请求口径；不可由平均 TPOT 倒推全系统吞吐。端到端 E2E 与生成部分时间的时间戳边界必须一致。

TTFT/TPOT 自洽分母有 output_tokens 和 output_tokens-1 等差异，按工具定义。单 token 输出在后一口径下没有有效 TPOT，不强凑值。工具分块/非流式返回可能让 TPOT 不代表生成速度，须看原始事件。

收益百分比由程序重算，方向和分母明示。延迟降低率=(基线-候选)/基线；吞吐提升率=(候选-基线)/基线；speedup=基线时长/候选时长。自然波动评估方法按设计选择，不统一规定三轮/5%/统计显著性即通过。缺足够证据时写尚未证实。

## 缺陷闭环

每项缺陷记录 issue ID、严重性、关联 claim/gate、原始位置、现象、影响、需要补的证据、负责人、复验条件。红线不被分数抵消。修复产生新一轮输出，不覆盖旧报告。权重/镜像/拓扑/补丁/手册/数据变更后由影响分析决定重检范围，并绑定新的包摘要。
